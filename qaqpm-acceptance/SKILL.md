# QAQPM-验收（S11）

笔记锚点：day17 六步执行侧；day13 功能测试 vs AI 评测；架构 §5。

## 1. 何时用 / 何时不用
**用**：开发可测之后做出入门禁判断。  
**不用**：改维度/权重/题型策略 → 回 S7。

## 2. 上游依赖
S7 门禁与黄金集（飞书模式以评测集多维表冻结视图＋本地镜像为准）；S8 验收用例；S10 变更与 bad case（飞书模式以 Bad case 多维表为准）。启用飞书时读 `_shared/feishu-doc-protocol.md`。

## 3. 目标与通过线
两套表都出：功能/流程测试；AI 效果评测。门禁结论明确：过 / 限范围 / 不过。综合分不得掩盖红线（day17）。
**报告第一句必须是决定**；对照 **S7** 执行，若要改指标／权重／题型策略 → 回 S7，本站不重开设计。

### 存储形态（飞书硬规则）
| 模式 | 功能验收用例权威载体 | 本地必有 |
|---|---|---|
| 本地-only | `11` 内功能测试表或 `qa/func-cases.md` | 本报告 |
| **飞书存储** | **飞书多维表格「功能验收用例」**（与 S7 评测集**分表**） | `11` 内镜像或 `qa/func-cases.md`；行数对齐 |

- 禁止把功能用例与黄金集混成一张多维表。
- AI 跑分仍引用 S7 冻结视图，不在本表改题。

## 开发仓库交接与发布前验收

有开发接入记录时，读 [_shared/development-kit-protocol.md](_shared/development-kit-protocol.md)，核对 `dev/开发接入.md`、仓库当前阶段、候选代码/配置和原始证据。没有接入记录的已有工程也可验收，不为验收自动 clone。

- 对照 S8 做功能/流程测试，对照 S7 冻结版本做 Agent 效果评测。S10 的真实冒烟、脚本自检和用户阶段验收分别是证据，不能单独替代两套验收结果。
- 相关代码、配置、环境和标准未变且覆盖充分时引用既有结果；发生影响时重跑相关检查，不机械重复无关付费调用。记录未提交改动快照，不能只写 commit。
- 核对共享协议第6节的冒烟失败、空前端检查、过期证据等边界；`verify.sh` 返回0不是单独的放行依据。失败/待验不得写通过，不适用附理由。
- 报告明确“发布前准入：过/限范围/不过”及允许用途；线上部署、登录隔离、持久化、域名、埋点采集尚未实测的列为 S12 待验，不写线上已验收。
- S11通过不自动执行部署；交 S12 在已授权目标内执行。只要求本地可用时交付本地结论与适用收尾，下一步可写结束而非强制上线。


## 4. 引导流程
P0 确认门禁版本与 storage_mode → P1 **飞书模式**：建/更新功能验收用例多维表与视图并镜像 → 执行功能测试 → P2 AI 评测执行（可 AI 裁判但须校准记录）→ P3 归因（失败可回写 Bad case 表）→ P4 报告与放行建议 → P5 交接。

## 5. 模板
`templates/11-验收与评测报告.md`（含两套表）；飞书细节见 `_shared/feishu-doc-protocol.md` §3.4。

## 6. 输出大纲
必填：存储形态与多维表 URL（飞书时）、环境与版本、功能测试表、AI 评测数据、典型案例、门禁结论、下一步。

## 7. 证据规则
分数附题量、运行次数、评分方式；案例附输入输出。

## 8. HTML
`reports/11-验收与评测.html` 优先支持。

`func_test_pass`, `ai_eval_pass`, `gate_result`, `storage_mode`, `func_case_bitable_url`, `func_case_md_mirror_path`, `development_binding_path`, `candidate_version`, `evidence_refs`, `online_pending_checks`, `next_station`→S12（仅本地目标可结束）

## 11. 回流
要改标准 → S7；要改实现 → S10；要缩范围 → S5。

## AI专题覆盖与运行证据

按[_shared/ai-document-protocol.md](_shared/ai-document-protocol.md)读取实际能力与S7对象映射。检查适用的模型／组件、Agent链路与结果、RAG检索与回答、生成／识别任务及整体流程；不要求不存在的组件／模态材料。

每个结论能追到标准、题集、对象／候选／配置、逐条运行Case、产物与分析。早期PoC只证明已测范围，不能替代系统准入。统计保留失败、超时、无产物、未运行及其分母规则；资料不足则相应范围待验或不通过，不靠报告文件存在放行。
