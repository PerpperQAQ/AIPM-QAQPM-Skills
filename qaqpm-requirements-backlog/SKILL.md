# QAQPM-需求池（S3）

笔记锚点：day12 需求池；框架阶段③；day13「103 条待办不能直接报老板」；飞书轻颜需求池表。

## 1. 何时用 / 何时不用
**用**：问题与调研已有线索，需整理成可管理条目。  
**不用**：还在争论是什么问题 → S1；已在排 MVP → 可与 S5 交错但池要先有索引。

## 2. 上游依赖
S1 问题卡、S2 原话索引与发现；可选竞品输入（后补）。启用飞书时读 `_shared/feishu-doc-protocol.md`。

## 3. 目标与通过线
每条需求有：来源、证据强度、假设标签、关联场景、状态、**痛点 ID**。禁止无索引写死「P0」。

**进池表述（默认拍板）**：  
**进池＝纳入管理与排序的默认池；资源承诺仍以 S5／S6 为准。**  
说不清重要性（谁痛、多痛、不做会怎样）的条目**不进池**，留在调研草稿或「观察」区。

### 存储形态（硬规则）

| 模式 | 权威载体 | 本地必有 |
|---|---|---|
| 本地-only | `03-需求池.md` 内需求表 | 本文件 |
| **飞书存储**（知识库/云文档为项目文档入口） | **飞书多维表格（Bitables）** | `03-需求池.md` **全字段只读镜像**（行数 ≥ 表内有效记录） |

- 用户采用飞书存文档时：**必须**用多维表格存需求池，禁止只用普通飞书文档里的 Markdown 表充当池。
- 多维表至少三个视图：全部需求、P0/首版候选、后续规划。
- 字段至少：ID、能力项、痛点/目标、建设方向、来源、提出方、状态、描述/PRD、证据编号、证据强度、假设标签、候选优先级、**痛点 ID**、验收题号、备注。
- `03` 文档内写清：多维表 URL、镜像说明、「进池≠资源承诺」。
- 无本地镜像或行数对不齐 → **S3 自检不通过**。

## 4. 引导流程
| Phase | 内容 |
|---|---|
| P0 | 汇总来源（用户/业务/竞品/内部）；判定 storage_mode=local\|feishu |
| P1 | **拆动作**：用户 → 需求 → 场景 → 问题 → 动作 |
| P2 | 填课件字段 + 证据列 + 痛点 ID |
| P3 | 状态机起步（常为「待评估」或「调研」） |
| P4 | 主题／备注分组；候选优先级注明未冻结 |
| P5 | **飞书模式**：创建/更新多维表与视图 → 写本地镜像 → 回读对账 |
| P6 | 输出池说明 +「未立项」声明 + 交接区 |

## 5. 方法与模板
`templates/03-需求池.md`（含轻颜「待评估」列映射【示例】与存储形态节）。  
飞书操作细节：`_shared/feishu-doc-protocol.md`。  
优先级正式在 S5 定；本站可标「候选优先级」并注明未冻结。

## 6. 输出大纲
| 章节 | 必/选 |
|---|---|
| 存储形态（local / feishu + 多维表 URL） | 必 |
| 池说明与统计 | 必 |
| 需求表（课件字段 + 证据增强 + 痛点 ID） | 必（飞书模式下＝本地镜像） |
| 轻颜式列映射说明（若用双轨表） | 选 |
| 主题归并 | 选 |
| 「进池≠资源承诺」声明 | 必 |
| 交接区 | 必 |

## 7. 证据规则
无来源条目不得进入「拟 P0 候选」。相关原话用编号引用。不粘贴外部需求池业务标题全文作「机密清单」。P0 候选无痛点 ID → 自检失败。

## 8. HTML
按需；默认 MD 即可。飞书多维表本身承担在线筛选，不强制另做 HTML 池。

## 9. 自检
- [ ] 每条有来源、状态、痛点 ID（P0 候选强制）
- [ ] 无「全部 P0」
- [ ] 可回溯到 research/ 或问题卡
- [ ] 声明已写：进池≠立项／资源承诺
- [ ] **若飞书模式：多维表已建且有三视图；本地镜像行数对齐；URL 写入 03 与交接区**

## 10. 交接区
`backlog_count`, `p0_ids`（仅候选）, `storage_mode`, `backlog_bitable_url`, `backlog_md_mirror_path`, `next_station`→S4 或 S5

## 11. 回流
来源被推翻 → 标废止并回 S2；与问题卡不符 → S1；飞书表与 MD 冲突未评审 → 先对账再进 S5。
