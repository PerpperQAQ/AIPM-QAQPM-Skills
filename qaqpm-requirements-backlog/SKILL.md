# QAQPM-需求池（S3）

笔记锚点：day12 需求池；框架阶段③；day13「103 条待办不能直接报老板」；飞书轻颜需求池表。

## 1. 何时用 / 何时不用
**用**：问题与调研已有线索，需整理成可管理条目。  
**不用**：还在争论是什么问题 → S1；已在排 MVP → 可与 S5 交错但池要先有索引。

## 2. 上游依赖
S1 问题卡、S2 原话索引与发现；可选竞品输入（后补）。

## 3. 目标与通过线
每条需求有：来源、证据强度、假设标签、关联场景、状态。禁止无索引写死「P0」。

**进池表述（默认拍板）**：  
**进池＝纳入管理与排序的默认池；资源承诺仍以 S5／S6 为准。**  
说不清重要性（谁痛、多痛、不做会怎样）的条目**不进池**，留在调研草稿或「观察」区。

## 4. 引导流程
| Phase | 内容 |
|---|---|
| P0 | 汇总来源（用户/业务/竞品/内部） |
| P1 | **拆动作**：用户 → 需求 → 场景 → 问题 → 动作（可先用 S2「用户-场景-需求」表） |
| P2 | 填课件字段 + 证据列 |
| P3 | 状态机起步（常为「待评估」或「调研」） |
| P4 | 主题／备注分组；候选优先级注明未冻结 |
| P5 | 输出池表 +「未立项」声明 |

## 5. 方法与模板
`templates/03-需求池.md`（含轻颜「待评估」列映射【示例】）。  
优先级正式在 S5 定；本站可标「候选优先级」并注明未冻结。

## 6. 输出大纲
| 章节 | 必/选 |
|---|---|
| 池说明与统计 | 必 |
| 需求表（课件字段 + 证据增强） | 必 |
| 轻颜式列映射说明（若用双轨表） | 选 |
| 主题归并 | 选 |
| 「进池≠资源承诺」声明 | 必 |
| 交接区 | 必 |

## 7. 证据规则
无来源条目不得进入「拟 P0 候选」。相关原话用编号引用。不粘贴外部需求池业务标题全文作「机密清单」。

## 8. HTML
按需；默认 MD 即可。

## 9. 自检
- [ ] 每条有来源与状态
- [ ] 无「全部 P0」
- [ ] 可回溯到 research/ 或问题卡
- [ ] 声明已写：进池≠立项／资源承诺

## 10. 交接区
`backlog_count`, `p0_ids`（仅候选）, `next_station`→S4 或 S5

## 11. 回流
来源被推翻 → 标废止并回 S2；与问题卡不符 → S1。
