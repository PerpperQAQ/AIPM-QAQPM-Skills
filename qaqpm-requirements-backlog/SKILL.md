# QAQPM-需求池（S3）

> **本轮增量 Changelog 2026-10-29**：硬分隔轻颜三层——用户-场景-需求禁止 R*；R* 仅待评估／正式池；飞书镜像行数不对齐＝S3 失败；交付报告贴行数。

笔记锚点：day12 需求池；框架阶段③；day13「103 条待办不能直接报老板」；飞书轻颜需求池表。

## 1. 何时用 / 何时不用
**用**：问题与调研已有线索，需整理成可管理条目。  
**不用**：还在争论是什么问题 → S1；已在排 MVP → 可与 S5 交错但池要先有索引。

## 2. 上游依赖
S1 问题定义、S2 原话索引与发现、S2「用户-场景-需求」中间表（若有）；可选竞品输入（后补）。启用飞书时读 `_shared/feishu-doc-protocol.md`。

## 3. 目标与通过线
每条**池内**需求有：来源、证据强度、假设标签、关联场景、状态、**痛点 ID**。禁止无索引写死「P0」。

**进池表述（默认拍板）**：  
**进池＝纳入管理与排序的默认池；资源承诺仍以 S5／S6 为准。**  
说不清重要性（谁痛、多痛、不做会怎样）的条目**不进池**，留在调研草稿或「观察」区。

### 轻颜三层硬分隔（P0）

| 层 | 是什么 | ID 规则 | 载体 |
|---|---|---|---|
| ① 原始记录 | 访谈／日志／问卷原件 | 无 R* | `research/` |
| ② 用户-场景-需求 | S2 中间分析表（阶段／场景／痛点／需求表述） | **禁止赋 R*** | 本地 MD／另表；**禁止**写入需求池多维表主视图当 R* |
| ③ 待评估／正式池 | 已拆成**可执行动作项**的 backlog | **仅此层用 R*** | `03-需求池.md` ＋飞书多维表 |

**反例（自检失败）**：把「阶段／场景／痛点」行直接编号 R01–Rn 当主池；bitable **单表混**中间层与池。  
**正例**：中间表 12 行 → 抽出 4 条可执行动作 → 赋 R001–R004 进待评估；中间表保留无 R*。

待评估区强制**证据强度**列；`mid-single`（单样本）**禁止**直接写候选优先级＝P0。`03` 须有专节「本轮新候选」与正式 R 表分区（或视图区分）。

### 存储形态（硬规则）

| 模式 | 权威载体 | 本地必有 |
|---|---|---|
| 本地-only | `03-需求池.md` 内需求表 | 本文件 |
| **飞书存储** | **飞书多维表格（Bitables）** | `03-需求池.md` **全字段只读镜像**；**行数必须对齐** |

- 用户采用飞书存文档时：**必须**用多维表格存需求池，禁止只用普通飞书文档里的 Markdown 表充当池。  
- 多维表至少三个视图：全部需求、P0/首版候选、后续规划。  
- 字段至少：ID、能力项、痛点/目标、建设方向、来源、提出方、状态、描述/PRD、证据编号、证据强度、假设标签、候选优先级、**痛点 ID**、验收题号、备注。  
- `03` 文档内写清：多维表 URL、镜像说明、「进池≠资源承诺」、**镜像行数／表行数**。  
- **无本地镜像，或行数不对齐 → S3 硬失败**；交付报告必须贴两侧行数。

## 4. 引导流程
| Phase | 内容 |
|---|---|
| P0 | 汇总来源；判定 storage_mode；确认中间层（若有）未带 R* |
| P1 | **拆动作**：仅将可执行动作项升入待评估；中间层保持分析表 |
| P2 | 填课件字段 + 证据列 + 痛点 ID；证据强度；禁 mid-single→P0 |
| P3 | 状态机起步（常为「待评估」或「调研」） |
| P4 | 主题／备注分组；候选优先级注明未冻结；「本轮新候选」专节 |
| P5 | **飞书模式**：多维表（禁混层）→ 本地镜像 → **回读行数对账** |
| P6 | 输出池说明 +「未立项」声明 + 人话交接 + 行数写入交付报告 |

## 5. 方法与模板
`templates/03-需求池.md`（含三层说明、待评估列映射与存储形态节）。  
飞书操作：`_shared/feishu-doc-protocol.md`。  
优先级正式在 S5 定；本站可标「候选优先级」并注明未冻结。

## 6. 输出大纲
| 章节 | 必/选 |
|---|---|
| 存储形态（local / feishu + 多维表 URL + **行数对账**） | 必 |
| 三层说明（中间层路径／为何未进池） | 必（有中间层时） |
| 池说明与统计 | 必 |
| 本轮新候选（与正式区分） | 必（有新候选时） |
| 需求表 R*（课件字段 + 证据 + 痛点 ID） | 必（飞书＝镜像） |
| 「进池≠资源承诺」声明 | 必 |
| 交接区（人话第一步 + YAML 附录） | 必 |

## 7. 证据规则
无来源条目不得进入「拟 P0 候选」。相关原话用编号引用。P0 候选无痛点 ID → 自检失败。mid-single 不得标候选 P0。

## 8. HTML
按需；默认 MD 即可。飞书多维表承担在线筛选。

## 9. 自检
- [ ] 中间层无 R*；R* 皆可执行动作项  
- [ ] bitable 未单表混两层  
- [ ] 每条有来源、状态、痛点 ID（P0 候选强制）；无「全部 P0」；mid-single 未标 P0  
- [ ] 可回溯到 research/ 或问题定义  
- [ ] 声明已写：进池≠立项／资源承诺  
- [ ] **飞书：多维表三视图；镜像行数＝表行数；交付报告已贴行数；URL 写入 03 与交接区**

## 10. 交接区
人话「接手后第一步」＋ YAML：`backlog_count`, `p0_ids`（仅候选）, `mirror_row_count`, `bitable_row_count`, `storage_mode`, `backlog_bitable_url`, `backlog_md_mirror_path`, `next_station`→S4 或 S5

## 11. 回流
来源被推翻 → 标废止并回 S2；与问题定义不符 → S1；飞书表与 MD 行数／内容冲突未评审 → 先对账再进 S5。
