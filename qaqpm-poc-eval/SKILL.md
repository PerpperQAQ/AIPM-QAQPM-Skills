# QAQPM-POC选型（S9）

笔记锚点：day13 POC·原型·MVP；day16 RAG/平台选型；day17 选型评测；飞书模型 List／国华选型；架构 §7.2 Archify。

## 1. 何时用 / 何时不用
**用**：验证关键能力成本与质量；输出技术链路演示；验证**运行时/协作底座**（不仅是模型）。  
**不用**：替代完整开发（S10）或正式准入（S11）。S5早期调用可在已授权的环境、数据和预算内实际验证，结论限定于已测可行性，返回S5/S6；条件不足时只交计划与阻塞，不伪造结果。

## 2. 上游依赖
读取S5关键假设、架构取舍与专题首稿，以及S7的标准和冻结样本。正式选型使用相应黄金集／子集及S8技术草稿；早期可行性模式不要求S6或S8终稿，S7可先为当前假设准备最小样本与判定。明确`evaluation_purpose`和`return_station`，规则见[_shared/ai-document-protocol.md](_shared/ai-document-protocol.md)。

## 3. 目标与通过线
先确定本轮是完整选型还是单项可行性验证。下列初筛、主辅、身份入口和技术链路展示仅对本轮涉及的对象展开；小实验不要求补齐无关部署、模型角色或HTML。

- 选型四步：**初筛 → 精筛 → 对比 → 主／辅**（模型 **或** 运行时底座）。  
- 模型初筛字段对齐模型 List schema（计费维度、单价、溯源 URL）；不整表搬价。  
- **运行时/协作底座**初筛另含：许可证、多用户边界、会话恢复、预览、信任域假设、官方插件/对接方式。  
- **身份入口**行：有官方候选须点名（如 Cloudflare Access＋Google、Tailscale），禁止只写模糊「反代」；未实测标【待确认】。  
- 冻结同一批样本；一次尽量只改一个主变量（day17）。  
- 产出：POC 结论、选型建议、是否缩 MVP、失败归因、技术链路 HTML。  
- 结果表默认 `not_run`；「通过」必须有证据链接。

## 4. 引导流程
| Phase | 内容 |
|---|---|
| P0 | 关键能力、失败代价、ToB/政策约束；回读 S5 架构取舍 |
| P1 | 冻结评测子集（从 **S7** 抽）与通过线 |
| P2 | **初筛表**（模型 List 与/或底座字段） |
| P3 | 精筛跑测；记录分项、GSB、成本；访问入口配置列入必测若 S5 已选 |
| P4 | 定主／辅；平台选型（现成 vs 框架） |
| P5 | （RAG）调优实验入口：切分／Top-K／混合权重／重排目标 |
| P6 | 写组件表（含 rag-offline/online 分组）→ HTML |
| P7 | 交接：早期验证回S5/S6，需求需细化回S8，开发条件齐备才交S10；失败回S5/S6 |

## 组件角色与证据

使用[组件与模型选型](templates/组件与模型选型.md)和[调优实验记录](templates/调优实验记录.md)。LLM、Embedding、Rerank及各生成／识别模型按实际架构选用；共享模型比较可多任务引用，系统效果另评。

每个实际跑次按S7[运行记录](../qaqpm-eval-design/templates/测试Case记录.md)关联对象、候选、样本、尝试、配置与原始证据；未执行保留not_run。Rerank比较说明相同候选集，Embedding说明语料／索引版本，生成任务保留实际产物和多次尝试。

## 6. 输出大纲
完整选型必填：适用对象的初筛表、候选、样本说明、结果表（含not_run）、成本、主辅结论、身份／访问入口（适用时）、组件表、HTML路径（已生成时）、对S5架构取舍的符合／偏差。早期单项验证可合订，明确假设、对象、标准／样本版本、配置、实际结果或阻塞、证据限制和返回站。  
选填：调优实验日志、序列图、Skill 调用稳定性。

## 7. 证据规则
不编造单价；查不到标【待确认】只给公式。不可一边给 A 多次挑最好、一边只取 B 首次。国华 POC 数字标【飞书原文示例】。官方 README ≠ 本环境已验证。

## 8. HTML
完整S9选型默认产出`09-技术链路.html`；S5早期单项验证或仅补选型表时按交付需要生成，不为一个小实验强制整套HTML。POC报告可用`reports/09-POC.html`。

## 9. 自检
以下按当前对象与交付范围检查，不适用项说明理由。

- [ ] 初筛含计费维度与溯源 URL（模型）或底座字段（运行时）
- [ ] 样本冻结且引用 S7
- [ ] 身份入口已点名候选或显式【待确认】
- [ ] 主／辅写清降级；结果未假装已跑
- [ ] HTML 与 MD 组件一致、可离线开
- [ ] ToB 项目写了国产化／私有化结论或【待确认】

## 交给开发的技术基线

按 [_shared/development-kit-protocol.md](_shared/development-kit-protocol.md) 接入 S10。除模型/底座外，列明主要终端、已有工程约束、已选技术与实际版本、验证证据、未验证项、降级方案及范围限制。固定技术选型表示记录本项目采用的基线，不强制所有项目使用同一框架。

S10 在技术适配声明中引用并说明采纳/偏差，不重新开放式选型或默认改回仓库技术栈。POC 仅覆盖已测能力，不能代替产品实现和 S11 验收；失败或条件通过时写清可实施范围。需要进入完整开发时由 S10 首次询问是否拉取指定 fork；本站不因 POC 自动 clone。

## 10. 交接区
`poc_verdict`, `tech_map_html`, `model_choice`, `backup_model`, `runtime_choice`, `access_entry`；增`evaluation_purpose`、`eval_object_refs`与`return_station`。next_station按本轮范围返回S5/S6/S8或交S10，不因一个早期实验自动开始开发。

## 11. 回流
不通过 → S5 砍范围或换方案 → 必要时 S6 改档位；指标争议 → S7。
