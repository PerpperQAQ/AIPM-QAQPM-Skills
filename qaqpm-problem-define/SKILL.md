# QAQPM-问题定义（S1）

笔记锚点：day12「01 把问题说清」；《AIPM完整流程框架》阶段①。

## 1. 何时用 / 何时不用
**用**：想法/老板一句话/功能名尚不清楚「谁在什么场景因何付出代价」。  
**不用**：问题卡已齐且仅缺调研证据 → 去 S2；已到写 PRD → 去 S8。

## 2. 上游依赖
总控索引；若已有 S2 材料可双入口先读调研再回填问题卡。读交接区 `facts_confirmed`。

## 3. 本站目标与通过线
**目标**：问题定义句中**找不到功能名**；一句话说清谁/场景/问题/凑合/代价。  
**通过线**：能通过「电梯测试」；AI 适用性有明确判断（是/否/部分/待确认）及理由。

## 4. 引导流程（一次一问）
| Phase | 问什么 | 跳过条件 |
|---|---|---|
| P0 | 原始表述是什么？（老板原话/自己想法） | 已粘贴 |
| P1 | 场景五要素：谁 / 何时何地 / 在做什么 / 卡在哪 / 现在怎么凑合 | 用户已给齐 |
| P2 | 频率与影响范围？ | 可标待确认 |
| P3 | 「有了它，你想解决什么？」→ 去掉功能名改写 | — |
| P4 | 问三次为什么（对照做过的事，不停在表面） | 已有根因假设 |
| P5 | 该不该用 AI：重复性高？可标准化？人力瓶颈？改流程能否更便宜？模型变强后壁垒还在吗？ | 非 AI 项目可简写 |
| P6 | 汇总问题定义卡，请用户确认 | — |

## 5. 方法与模板库
- 三步：还原场景 → 分开问题与方案 → 问三次为什么（day12）。  
- AI 三条件 + 两追问（day12）。  
- 模板：`templates/01-问题定义卡.md`

## 6. 输出文档大纲（01-问题定义卡.md）
| 章节 | 必填/选填 |
|---|---|
| 原始诉求（含功能名原文） | 必填 |
| 场景五要素表 | 必填 |
| 一句话问题定义（禁功能名） | 必填 |
| 根因假设（各标标签） | 必填 |
| AI 适用性判断 | 必填（AI 项目） |
| 非目标 / 不在本问题内 | 选填 |
| 交接区 YAML | 必填 |

## 7. 证据规则
每条根因假设标【事实｜推断｜待确认】。无调研时允许【待确认】，但不得写成已验证痛点。

## 8. HTML
默认不出 HTML；若用户要可视化，用公共壳输出「场景五要素 + 问题句 + AI 判断」一页。

## 9. 自检
- [ ] 问题句无功能名  
- [ ] 五要素齐全或显式待确认  
- [ ] AI 判断有理由  
- [ ] 标签齐全

## 11. 回流
