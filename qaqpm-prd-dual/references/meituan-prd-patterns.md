## 1. 生成 → Judge → 人工闭环【示例】

1. 用户输入（如菜品名）  
2. Query 增强  
3. **路由**至多个知识库之一  
4. 向量检索 Top-K（文中 Top-20）  
5. Rerank 取 Top-N（文中 Top-5）  
6. 拼装 Prompt 生成  
7. 返回文案 + 参考来源  
8. AI 自动评测  
9. 综合分 ≥ 阈值 → 发布；否则 → **人工复核**

PRD `08-AI能力与评测验收.md` 必须有「闭环」小节，写清阈值与转人条件（链 S7 门禁版本）。

## 2. 多知识库路由【示例结构】

| 知识库 | 内容范围 | 分块策略要点 | 用途 |
|---|---|---|---|
| 事实库 | 关键事实长文 | 按语义／章节，设 chunk 与 overlap | 生成依据 |
| FAQ 库 | Q&A 对 | 每对一块 | 高频关心点 |
| 文化／背景库 | 中长文背景 | 按段落 | 文案背景 |

原则：不能全部塞进一个库；按查询模式路由。

## 3. 清洗四层【示例】

1. **通用格式**：去装饰符、页眉页脚水印、统一全半角；抽出更新日期进元数据。  
2. **图片**：照片→alt；图表→描述；截图→OCR；难例→专用 OCR。  
3. **表格**：拆 Sheet、拆合并单元格，转 JSON／MD／HTML 再入库。  
4. **人工抽检**：每批随机约 **10%**；错文档打「待审核」不进正式库。

## 4. Chunk 元数据必带字段【示例 · 11 字段】

chunk_id｜业务主键名（如 dish_name）｜过滤标签（如 region）｜类目｜source｜chunk_type｜content_category｜last_updated｜owner｜review_cycle｜content  

换业务时改字段名，保留「可过滤、可溯源、可路由、可审阅周期」。

## 5. 团队角色职责表【示例】

| 角色 | 职责 |
|---|---|
| 产品经理 | 需求、PRD、验收 |
| 算法 | 知识库、RAG、评测模型 |
| 后端 | API、库表、集成 |
| 前端 | 管理后台、评测看板 |

可扩「角色-姓名-职责」项目组表（见 `05-角色和权限.md`）。

## 6. 指标分层【示例 · 脱敏阈值须重定】

| 层 | 示例指标方向 |
|---|---|
| 检索层 | Recall@K、Precision@N、MRR、检索 P95 |
| 生成层 | 准确率、相关性、Judge 综合分、生成 P95、达标率 |
| 业务层 | 相对人工耗时、复核率、发布率、知识覆盖率、可用性 |

## 7. 风险模式【示例方向】

覆盖率不足 → 统计后延期；模型接口不稳 → 重试+降级；Judge 误判 → Golden Set 校准+保留人工；清洗质量 → 抽检阈值；时延超标 → 压测与异步。

验收 P0 方向：入库成功率、端到端时延、**必须展示参考来源**、无资料时明确提示而非静默生成、低分自动高亮。
