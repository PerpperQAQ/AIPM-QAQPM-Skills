# QAQPM-MVP范围（S5）

笔记锚点：day13「05 排出先后」；框架阶段⑤；高德缩范围案例。

## 1. 何时用 / 何时不用
**用**：从需求池收到第一版最小闭环。  
**不用**：还在验证痛点 → S2；已立项只改 PRD 细节 → S8（重大砍范围仍回本站）。

## 2. 上游依赖
S3 池、S4 差异化、S1 问题；技术高风险时可读 S9 草案。长讨论须对照 `research/已确认决策表.md`。

## 3. 目标与通过线
推导顺序：**业务目标 → 目标人群 → 链路问题 → 需求 → 优先级 → 资源**。  
MVP 五件事齐：核心假设／必须做／明确不做／以后再说／通过标准。  
**must 每条必须连回痛点 ID**；不做须写理由。全部标 P0 = 未完成排序。  
**架构取舍表必填**（缺执行位置 → 本站不通过）。

## 4. 引导流程
P0 业务目标 → P1 人群与卡点 → P2 Kano → P3 价值成本 → P4 范围表（含痛点 ID）→ P5 **架构取舍表** → P6 通过／止损 → P7 **分阶段闸门**（与 S6 条件立项交叉）→ P8 可选插队 S9 草案。

## 5. 方法与模板
`templates/05-MVP范围.md`（含 POC／原型／MVP 表、闸门表、架构取舍表）。

### 架构取舍（必填）
| 维度 | 本版选择 | 后置/不做 | 标签 |
|---|---|---|---|
| 执行位置 | 公共执行 / 个人 Runner / 混合 | | 【事实】或【推断】 |
| 同时活跃任务/Agent | | | |
| 访问入口 | 如 Cloudflare Access＋Google / Tailscale / … | | |
| 租户与权限 | 单团队可信小组 / 多租户… | | |
| 代码与工作区 | 随执行机器 / 仅 Git… | | |

讨论已收敛的取舍必须落入本表，不得只留在聊天。S6/S9 必须引用本表。

## 6. 输出大纲
必填：目标、假设、必须／不做／以后（含痛点 ID）、**架构取舍**、通过标准、闸门。选填：分期路线图。

## 7–11
证据：通过标准数字若为教学示例不可照搬。HTML 按需。自检：有不做理由、must 连痛点、闸门不过有动作、**架构取舍完整**。交接 → S6（含 `mvp_must`/`mvp_wont`/架构摘要）。回流：POC 失败缩 must；差异化能力被砍 → S4。
