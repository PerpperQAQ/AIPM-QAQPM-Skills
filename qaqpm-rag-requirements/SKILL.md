# QAQPM · RAG需求与架构

先读 [_shared/ai-document-protocol.md](_shared/ai-document-protocol.md)。围绕业务知识任务写方案，不把向量库或某个框架当作默认答案。

## 工作方式

1. 从用户问题、目标答案和现有资料还原知识任务；读取已有PRD、范围与数据说明，确定首稿／开发交接深度。
2. 先查知识是否存在、能否取得、权限与更新责任；资料不足作为范围和可行性条件，不编造语料规模或授权。
3. 按模板写清离线知识处理和在线检索生成。每个节点列输入、输出和上下游字段，明确候选数、排序与上下文预算的关系。
4. 从实际架构确定组件：LLM、Embedding、Rerank、关键词检索、图谱等。未采用项说明不适用；规则排序不冒充已选Rerank模型。
5. 复用S7的组件／检索／系统评测设计和S9的模型选择、调优日志；早期验证返回S5/S6，实际结果回写原需求。
6. 交接知识版本、索引版本、可复现配置、引用与更新规则及未决事项。更换Embedding、切分或索引时说明重建、回退与回归范围。

## 交付检查

- 用户问题能追到知识范围；知识缺失、过期、冲突与无权限都有产品行为。
- 离线和在线流程输入输出一致；候选数和上下文限制前后相容。
- 原始文档、片段、检索结果和最终引用可关联，来源与版本可定位。
- 已区分组件选型、检索排序与系统回答的评测对象；无结果或碰巧答对不被隐藏。
- 权限过滤覆盖检索、上下文、引用与缓存等实际环节；只补与本业务有关的约束。
- 未跑实验仍标待验证；S5未知参数有验证计划，S8交接版关键规则可执行。

交接可补：`ai_document_index_path`、`capability_ids`、`document_maturity`、`knowledge_refs`、`eval_object_refs`、`return_station`。
