# QAQPM-发布与上线观察（S12）

分清开发完成、发布前验收通过、线上验证通过、用户价值成立。只要求本地交付时不自动进入部署。

## 1. 入口与资料

**用**：S11 已给出指定范围准入结论，用户准备发布；或已有线上产品需要观察与迭代。
**不用**：用灰度代替测试；把全量使用数据当成因果证明；用部署成功代表 Agent 效果达标。

读取 S11 结论/限制、S8 产品目标、S7 标准、S3 需求池与现有上线资料。有开发仓库绑定时读取 [_shared/development-kit-protocol.md](_shared/development-kit-protocol.md) 和 `dev/开发接入.md`；仅做线上观察不要求 clone。已有工程只在明确需要接入仓库时回 S10 处理首次确认与适配。

飞书模式读 `_shared/feishu-doc-protocol.md`，线上问题续写同一份 S10 Bad case 多维表及镜像。

## 2. 发布前准备

1. 确认候选版本、目标环境、发布人群、已有授权、费用边界、停止和回滚条件。S11通过不等于发布授权；已有明确授权不重复索取。
2. 按图核对服务器/运行环境、数据库/迁移与备份、登录/用户隔离、域名或平台测试地址。写明选定方案、已配置项与待验项；平台测试地址不冒充自有正式域名。
3. 埋点引用 S8/S10 已确定的产品问题、事件和指标口径，缺失则先补最小方案。不得拖到上线后才开始考虑数据归属和权限。
4. 使用仓库时读实际部署手册及适用参考代码，沿用其阶段4上线方案摘要、证据包、阶段工具；CloudBase是该仓库默认路径，其他平台需适配，不静默替换已定方案。价格、CLI、平台能力在使用时核实，不照旧手册当现状。

## 3. 部署与线上验证

在授权范围内执行部署；不因任务文件写着阶段4而擅自发布、购买资源、改域名或向用户发送消息。按仓库运行任务/自检/验收推进，遇缺口留在相应阶段。

目标环境检查至少覆盖适用项：
- 外网可访问、实际运行版本正确、健康状态正常。
- 真实用户完成核心业务闭环；权限场景用两个账号检查隔离。
- 业务数据与需要恢复的状态可持久化；迁移、上传等仅在实际验证后标通过。
- 实际模型链路、结构与错误返回、耗时/成本符合本次发布要求；引用 S7/S11，部署变化补相关验证。
- 域名/HTTPS/回调配置与目标一致；回滚方法可执行，未演练则如实说明。
- 埋点做一次真实操作，检查事件实际送达、字段与去重/口径正确；不记录密钥、完整敏感输入，不让埋点失败阻断主功能。

自检原始结果、补充核查、用户阶段验收均保留。阶段5按仓库做适用收尾，确认退出本机登录后服务仍可用，说明运行凭证依赖和到期项；不删除线上仍依赖的凭证。仓库“完成”只代表其工程流程结束，不代表本节后面的观察已完成。

## 4. 上线后：Agent 效果、数据、反馈

1. 按产品和证据选择灰度 / A·B / 全量及人群。观察窗口和样本来源写清；A/B也须有合理分组与分析设计，不自动保证因果。
2. **Agent 效果验证**：线上样例引用模型/Prompt/代码/标准版本，评估效果、错误、延迟和成本；真实线上分布与离线题集分别报告，样本不足写待观察。
3. **数据分析**：围绕是否使用、在哪一步卡住、结果是否采用，记录指标分子/分母、时间窗、版本、人群、样本量与基线；没有采集到数据不得填推测数字。
4. **用户反馈**：记录来源、原意、场景与证据，区分意见、观察与已验证缺陷。联系用户/发消息需有相应授权；可先分析用户已提供的反馈。
5. 新错误先写 `eval/online/` 和现有 Bad case；是否升入 `eval/gold/` 由 S7评审并产生新版本。需求回 S3，标准问题回 S7，实现问题回 S10，必要时回 S11复验。
6. 输出继续/缩小/暂停的建议，不把“有网址”当成效果或业务价值证明。不因“上线观察”自动建立定时任务；持续监控需另有请求。

## 5. 输出与模板

沿用 [templates/12-上线观察.md](templates/12-上线观察.md)，包含发布前结论引用、环境与版本、部署/线上待验项、埋点检查、观察窗口、三类观察、回流和下一步。

有绑定仓库时引用原部署证据；没有则记录当前项目的真实发布证据，不要求伪造仓库阶段。`reports/12-上线观察.html`按交付需要生成。飞书同步回读状态与工程结果分别报告。

## 6. 自检

- [ ] S11结论和本次发布范围一致；发布有授权或明确尚未执行
- [ ] 服务器/数据/登录/域名适用项逐项验证；未拿测试地址冒充正式发布
- [ ] 埋点有真实采集证据，或明确待验/不适用及理由
- [ ] 线上Agent效果、数据、用户反馈分开报告；版本、人群、时间窗与局限清楚
- [ ] 新问题续用原Bad case并回流；题集变更未覆盖旧评测依据
- [ ] 工程收尾与用户价值观察区分；未虚构线上使用或擅自创建自动监控

## 7. 交接

沿用共享交接协议，记录 `development_binding_path`（如有）、`candidate_version`、`release_status`、`online_verification_status`、`telemetry_status`、`observation_window`、`release_mode`、`evidence_refs`、`backflow_to_backlog`。下一站按原因是 S3/S7/S10/S11，定位动摇回 S1；观察数据未齐可留在 S12。
