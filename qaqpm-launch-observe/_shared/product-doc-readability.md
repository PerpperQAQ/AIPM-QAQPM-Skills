# QAQPM · 产品文档可读性短规

> Changelog 2026-10-29：新建。与 `human-writing` 划界——QAQPM 产品包（01–12、00 索引、立项决策一页纸、research/、飞书镜像）走本短规，**不**套用散文的冒号／破折号／翻案句硬禁令。

## 何时用

- 写或改 QAQPM 站交付（MD / HTML 壳 / 飞书文档正文 / 多维表说明）。
- 总控润色「给人读」的开篇、证据边界、已决｜待证、交接人话。

## 何时不用

- 对外长帖、知乎、口播、演讲、故事 → 用 `human-writing`。
- 代码、YAML 交接附录、CSV／多维表字段名 → 不受本短规文风约束（仍遵守 handoff／feishu 协议）。

## 去课件味标题

| 避免作对外主标题 | 优先展示名（站号可留副标） |
|---|---|
| 问题定义卡 | 原始需求与问题定义 |
| 共享决策包 | 立项决策一页纸 |
| AI 三问与质量闭环（单独当章名唬人） | 写清「AI 做什么／不做什么／怎么验收」 |
| 双轨 PRD／门禁（作索引主标题） | PRD（给人）／开发与接口约定；门禁放验收章 |
| 08A Agent 规范（对外） | 开发与接口约定（Agent 规范可作副标） |

默认**文件名可保留站号**（如 `01-问题定义卡.md`）；**00 索引与飞书标题**用展示名，禁止对外主标题堆「卡／双轨／门禁／闭环」课件词。

## 禁用营销黑话（产品包）

正文避免空转：`赋能`、`打通`、`着力点`、`抓手`、`闭环生态`、`一站式全面`（无具体对象时）。  
有具体系统／接口／角色时，直接写对象与动作。

## 证据边界红条

凡含测算、外部经验、单样本、官方文档记载的交付，**页首或关键块上方**须有短红条（可用引用块），至少锁死：

- 相关 ≠ 因果  
- 外部经验 ≠ 本团队已量化  
- 测算 ≠ 已上线成果  
- 官方记载 ≠ 本项目已验证  

细节标签纪律见 `labels.md`；红条扛总纪律，正文按段／表列标注，禁止逐句堆标（见 labels 密度规）。

## 已决｜仍要证明

立项相关一页纸必须让人一眼看到两栏或对照表：**已经决定的**｜**仍要证明／未冻的**。  
`frozen=false` 时索引与一页纸顶部红字「决策未冻」，不得标 S8 终稿。

## 交接给人读

正文交接区先写「接手后第一步」人话（见 `handoff-schema.md`）；YAML 仅附录。
