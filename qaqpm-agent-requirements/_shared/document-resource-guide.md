# 文档资源类型与覆盖

用途：查明本次文档应该参考哪里、模板覆盖到什么程度。按项目实际范围选用，不能将资源数量当作阶段完成度。

## 1. 三种主要支持类型

| 类型 | 定义 | 使用方式 | 计数边界 |
|---|---|---|---|
| 独立模板 | `templates/` 中具有实质内容的 Markdown 文件 | 在项目既有路径填写／更新。部分是完整字段表，部分只是章节骨架 | 按文件计，不等于独立报告数量；PRD 的各章节分别计文件 |
| 正文大纲 | `SKILL.md` 中的输出章节、工作方式或交付要求 | 按对应章节组织结果，与模板配合；无独立模板时直接按结构交付 | 是原文章节入口，不算新增模板 |
| 共享规则 | `_shared/` 的证据、交接、存储、AI 文档和开发协议等 | 约束适用的跨站交付，先读与本次任务有关的部分 | 按根目录去重；各 Skill 内副本不重复计数 |

CSV 是配套文件；旧名重定向只用于保留链接，不计入独立模板。含“独立模板”标签只说明载体存在；“章节骨架”说明内容较简，需要结合正文大纲与共享规则展开。独立模板不等于填好示例，也不等于开发、模型或验收已验证。

合计 **84 个独立 Markdown 模板文件、1 个 CSV 配套文件、1 个旧名跳转文件**（templates目录合计86文件）。其中章节骨架不是另一套模板：计入84，同时标明内容深度。正文大纲入口与共享规则单独展示和统计，不与84相加声称“模板总数”。实际文件变化后重新统计，禁止将本页日期数当永远不变的现状。

## 3. 完整性的边界

- 12站主要文档已有独立模板；四项曾缺独立文件的结构已补齐。其他产物可以通过正文、共享协议或绑定工程材料支持，不能声称所有可能交付物都有独立文件。
- S8 薄模块可按用户项目补细节；本轮未将每个章节扩写为完整示范报告。
- 飞书四表是存储形态要求，模板不能代替建表、实际写入、行数对账与回读。
- 代码、日志、截图、真实运行、访谈原件和上线数据由实际工作产生，不用模板补造证据。
