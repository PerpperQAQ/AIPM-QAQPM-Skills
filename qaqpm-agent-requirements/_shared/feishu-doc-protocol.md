# QAQPM · 飞书文档交付协议

> Changelog 2026-10-29：增导入失败／Untitled 清理／回读行数操作红线；写入成功≠内容正确列入交付 blockers。  
> 当项目文档落在**飞书知识库 / 云文档**时遵守本协议。本地-only 项目可跳过，但下列「表状」交付仍须有可审阅的表（MD/CSV 即可）。

## 1. 何时启用

用户明确要求「写到飞书」「Wiki 子文档」「飞书知识库」或项目索引以飞书 URL 为权威入口时启用。

## 2. 子文档与站序

| 站 | 飞书子文档标题（建议展示名） | 本地镜像 |
|---|---|---|
| 索引 | `00 项目全景`（可副标站序） | `00-项目索引.md` |
| S1–S12 | 用展示名（见 lifecycle 去课件味表） | 同名或站号文件名 `.md` |
| 决策 | **立项决策一页纸** | `立项决策一页纸.md`（旧名共享决策包可重定向） |

- 在父节点下**创建子文档**，不要把全站揉进一篇长文（除非用户只要单页摘要）。
- 发布后回写 `发布材料/published-nodes.json`（或等价）：`key → node_token / document_id / url`；并与 `00` 文档清单对账。

## 3. 必须用飞书多维表格的表

**规则（硬）：项目文档采用飞书存储时，下列权威载体 = 飞书多维表格（Bitables），禁止只用普通飞书文档里的 Markdown 表充当。**

定性长文（问题定义、立项报告、PRD 正文、竞品分析叙事与对照、技术链路 HTML 等）仍用普通文档/页面；**竞品不强制、也不默认进多维表**。

### 3.1 需求池（S3）— 硬

| 项 | 要求 |
|---|---|
| 创建 | 在同一 Wiki 空间下建「需求池」多维表（或 Base）；索引页与 `03 需求池` 文档内放入口链接 |
| 分层 | **禁止**单表混「用户-场景-需求」中间层与 R* 池；中间层另表或仅本地 MD；R* 仅待评估／正式池 |
| 字段 | 至少覆盖：ID、能力项、痛点/目标、建设方向、来源、提出方、状态、描述/PRD、证据编号、证据强度、假设标签、候选优先级、痛点 ID、验收题号、备注 |
| 视图 | 至少：全部需求、P0/首版候选、后续规划（名称可本地化） |
| 本地镜像 | **必须**另有 `03-需求池.md`（或同名）含**只读全表镜像**或可导出的 CSV/MD 表；**行数必须与多维表有效记录对齐** |
| 冲突 | 以评审后的双写为准；行数不对齐或未对账 → **S3 硬失败**，不得宣称通过 |

### 3.2 评测集 / 黄金集（S7）— 硬

| 项 | 要求 |
|---|---|
| 创建 | 建「评测集」或「黄金集」多维表；索引页与评测设计文档内放入口链接 |
| 字段 | 至少：题号、题型（正常/边界/红线/反例）、场景标签、输入摘要、预期要点、适用维度、来源（真实/专家/AI）、状态（草稿/冻结）、门禁版本、备注；RAG/Agent 项目追加检索可核对字段 / 过程检查点 |
| 视图 | 至少：全部题目、红线题、本轮门禁冻结集 |
| 本地镜像 | **必须**另有 `eval/` 下索引全字段镜像；行数对齐；单题细节可仍用 `eval-item` 文件 |
| 冲突 | 未对账前不得宣称 S7 黄金集 v0 已就绪；S11 跑分以冻结视图为准 |

### 3.3 Bad case / 缺陷回流表（S10 起，S12 续写）— 硬

| 项 | 要求 |
|---|---|
| 创建 | 建「Bad case」多维表；开发推进／上线观察文档内放入口链接 |
| 字段 | 至少：ID、发现站、现象摘要、复现步骤或输入、期望 vs 实际、归因、严重度、状态、是否回写评测题、关联需求 ID、负责人、备注 |
| 视图 | 至少：未关闭、本迭代新增、已回写评测集 |
| 本地镜像 | 行数对齐 |
| 冲突 | 未对账前不得宣称「bad case 已闭环」 |

### 3.4 功能验收用例表（S11，≠ AI 评测集）— 硬

| 项 | 要求 |
|---|---|
| 创建 | 建「功能验收用例」多维表（与 3.2 **分表**） |
| 字段 | 至少：用例 ID、模块/场景、前置、步骤摘要、期望、实际、状态、阻塞原因、关联需求 ID、执行人、日期、备注 |
| 视图 | 至少：本轮必测、失败与阻塞、全量 |
| 本地镜像 | 行数对齐 |
| 冲突 | 功能用例表 ≠ 黄金集 |

普通飞书文档里贴一张 Markdown 表**不满足** 3.1–3.4。

## 4. 操作红线（P0）

1. **导入／粘贴失败 → 停写**：立即记入交付 `blockers` 与 `00` 开放问题；禁止改用「写入成功」话术蒙混；禁止在错误父节点继续堆文档。  
2. **禁止留下 Untitled**：创建失败、标题未改、空页残留必须删除或改名；清理清单写入交付报告。  
3. **回读核对**：写入后必须回读——核对**标题**、**关键表／多维表行数**、链接可点、【事实｜推断｜待确认】未丢。  
4. **写入成功 ≠ 内容正确**：CLI／API 返回成功只证明请求抵达；内容对错以回读为准。回读未做 → 不得标该站飞书交付通过。  
5. **路径与体积**：CLI 文件路径须落在允许根；大内容用 `@file`；路径不在允许根 → 停写并记 blocker。  
6. **权威根**：`00`、`03`、立项决策一页纸必须能在**同一权威根**（本地项目根或约定飞书父节点）找到；与 `published-nodes` URL 对账，冲突未评审不得标通过。

## 5. 双写与回读

1. 先写本地 MD（或先写多维表，再立刻镜像）→ 再写入飞书。  
2. 写入后 `docs +fetch` / Base 读回：标题、行数、链接、标签。  
3. 交付报告必须贴：**各多维表 URL**、**镜像行数 vs 表行数**、Untitled／失败清理清单、未同步项。

## 6. 自检（飞书模式）

- [ ] 子文档按站创建且索引可点开；无 Untitled 残留  
- [ ] **需求池为多维表格**，三视图；本地 `03` 镜像**行数对齐**（写入交付报告）  
- [ ] **评测集／Bad case／功能验收**按进入站要求建表且镜像对齐；竞品不进多维表硬规则  
- [ ] 立项决策一页纸非空壳；未冻则索引标红  
- [ ] 导入失败已停写并进 blockers；回读完成  
- [ ] 未把「写入成功」当成「内容正确」

## 7. 开发仓库与工程证据

开发接入遵循 [development-kit-protocol.md](development-kit-protocol.md)。PRD、标准、需求池等沿用本协议权威位置；代码和机器产生的测试日志、截图、部署产物留在工程仓库/约定证据存储，不能把本地工程目录误称飞书权威副本。

- 原四表继续复用，S10/S12 不另建与既有题集、Bad case脱节的表。
- 飞书主文档/表记录证据摘要、版本和链接；读者无法访问本地路径时明确说明，按分享需要提供经脱敏的可访问证据，不宣称链接可用。
- 文档同步按约定的里程碑交付进行，不要求每次代码修改上传全部原始日志。
- 工程验证状态与文档同步状态分别记录；同步失败/未回读不得标飞书交付完成，但不把已实际通过的工程测试改成失败，也不因工程通过掩盖同步缺口。

## 8. AI专题与配套表（按项目能力启用）

参考合集用于取材，不能因可读取就当作项目发布目标；输出仍使用用户指定的项目目录。只读取飞书参考不等于启用飞书存储交付。

- Agent/RAG/AIGC需求及流程、Prompt、架构等长文作为普通文档，可按项目规模合订；S5创建后S8更新同一逻辑文档与URL。
- Tool List、知识来源台账、运行Case、素材登记等持续维护的表优先复用现有Base／Sheet；单次小表可用MD/CSV。原3.1–3.4四表规则保持，新增表不自动成为所有项目硬门槛。
- 评测集只保存样本与预期；运行Case以run_id、object_id、candidate_id、case_id、attempt_id关联，使用独立记录表或等价明细，不能反复覆盖冻结题目中的成绩。
- Base字段映射采用S7测试Case、专题Tool List与知识来源等模板；记录文本、枚举、数字、URL和关联字段的实际类型，不把复杂结构静默截断成短文本。
- 已有表缺字段时只补必要字段，保留记录ID和历史；读取全字段、写后按记录ID回读，核对行数、版本、关键字段与引用。公开分享时确认原始证据引用是否可访问。
- 更新现有长文先读取完整内容与revision，按工具支持的修订保护写入，再取回核对；CLI以ok=true／实际退出状态与回读结果判断，不只看顶层code。

索引记录能力ID、文档／表URL、本地镜像、成熟度和同步状态。文档同步完成与模型／链路／产品验证分开报告。
