# QAQPM-竞品分析（S4）

笔记锚点：day13「04 看清对手」五步；day11 五层；OiiOii 市场三层；框架阶段④。

## 1. 何时用 / 何时不用
**用**：回答别人做了吗、凭什么是我们。  
**不用**：纯自我拆解练习且无竞争决策 → 用 S6 拆解模块即可。

## 分析模式：先按用户目的确定范围

| 模式 | 何时选 | 执行与产出 |
|---|---|---|
| 竞品扫描 `scan` | 找市场空位、筛选对手、跟踪动态，尚不要求完整体验 | 竞品地图、市场与公开材料比较；在[竞品分析模板](templates/04-竞品分析.md)中标清未体验部分，可完成扫描，不能称已完成产品实测 |
| 单功能研究 `feature` | 研究一个功能、环节或具体设计取舍 | 使用[功能分析报告](templates/功能分析报告.md)，完成同任务的相关链路与异常取证，只拆影响决定的层 |
| 完整产品拆解 `full_teardown` | 用户明确要求完整体验、深拆，或需要依据端到端表现选择关键竞品 | 先确定要深拆的产品与任务，逐产品调用[五层五问模块](../qaqpm-go-nogo/references/teardown-module.md)，形成体验记录、五层附录与架构图，再横比和下结论 |

从请求中能确定模式时直接执行，报告开头写明模式与范围。完整拆解不要求把竞品地图上的所有产品都深拆；明确本轮目标产品。若无法实测，保留原任务目标并交付“二手材料分析／待补实测”，不得为了宣称完成而静默降为扫描。单功能不强制市场规模、全产品商业化、五层齐全或百分制评分。

## 2. 上游依赖
按本次决定读取已有 S1/S2/S3 的用户、任务与需求证据；单项研究可直接开始，不要求补齐无关前序文档。

## 3. 目标与通过线
- 扫描或完整竞品分析先明确主要目的：0→1 找空位／1→N 找增量／对手出招跟不跟／潜在进入者威胁；单功能写清具体设计决定即可。  
- 差异化公式：盯 X 用户，最在乎 Y，竞品做不了因 Z（Z 有依据）。  
- **必须有反方论证**（可用固定唱反调 prompt）。  
- AI 产品看完整输出物，不只看有没有按钮。
- 完成标准按模式核对。完整体验至少有一次真实场景的主流程记录和一次相关异常操作，异常四类逐项记录已测／未测／不适用及依据；更高的覆盖要求服从本次研究目的。材料不足时只能交付已完成部分。

## 4. 引导流程
P0 **定目的、模式与范围** → P1 选择可比产品（扫描／完整分析包含四类竞品与市场层）→ P2 定同一任务、输入、环境与判据 → P3 取证与体验 → P4 比较、差异化与唱反调 → P5 检查完成范围并交接。

**P3 按模式执行**：扫描按公开来源整理；单功能按功能模板体验相关链路；完整拆解必须先读并执行[拆解流程](../qaqpm-go-nogo/references/SKILL.md)与[体验指南](../qaqpm-go-nogo/references/experience-guide.md)，使用[拆解表格](../qaqpm-go-nogo/references/templates.md)。每个目标产品保留体验记录、异常覆盖、截图／输出索引及五层附录。先取得证据再进入 P4，不能只填五行横比表代替深拆。

### 收信息四处纪律
1. 体验研究使用同一用户任务，记录输入、产品版本／日期、账号档位、环境限制、截图及真实输出。公开演示与亲自操作分开记录。  
2. 官网／定价／文档／更新日志（标日期）。  
3. 用户公开反馈（转成可复现任务，差评≠已验证需求）。  
4. 招聘／融资／专利仅作线索，标【推断】或【待确认】。

不能实测时，记录已取得的材料和待补步骤；请求接管或发出截图清单只代表等待补证。用户提供的实际截图／录屏须能追溯操作与结果，才能据此标明覆盖范围，不能改称 Agent 亲测。

## 5. 方法与模板
- [竞品分析](templates/04-竞品分析.md)：主报告、逐产品证据与拆解附录索引。
- [功能分析](templates/功能分析报告.md)：限定功能范围的同任务比较。
- [反方论证](references/devil-advocate-prompt.md)。
- [五层五问模块](../qaqpm-go-nogo/references/teardown-module.md)：流程、体验、表格和推断方法的共享入口。

## 6. 输出大纲
模式与决定｜目标产品与可比任务｜证据及完成范围｜竞品地图／市场层（按模式）｜同维对比｜差异化一句话｜反方论证｜单品拆解附录索引（完整模式必有）｜交接区。

体验记录、异常覆盖和截图／输出索引可合订在主报告或附录，使用真实路径或章节链接。未创建文件写“待创建”，不能用空路径代表已交付。

## 7. 证据规则
页面事实／推断／待确认；融资招聘仅为线索。官方说法与真实操作结果分别记录；UI 角色、进度、选项和推荐列表不能单独证明内部 Agent、工具或 RAG 实现。技术判断保留依据、其他可能解释及核实办法，见[方法工具箱](../qaqpm-go-nogo/references/toolkit.md)。标签别名见 `_shared/labels.md`。

## 8. HTML
`reports/04-竞品分析.html`；深拆可用 teardown 模板。

## 9. 自检
- [ ] 模式、要支持的决定、目标产品和任务范围明确
- [ ] 同任务输入与环境可比；无法等价的条件和未体验部分已说明
- [ ] 扫描／完整竞品分析包含替代方案与市场层；单功能只检查相关范围
- [ ] 完整模式逐产品有主流程与至少一次相关异常的真实证据、四类异常覆盖状态、五层附录及架构图；未达到时明确写待补实测，不能勾选体验完成
- [ ] 单功能模式有相关链路、结果和异常证据或明确缺口，不因缺少其他层而判未完成
- [ ] 每项比较能回到证据；推断与事实分开，未知内容没有补写成事实
- [ ] 有反方论证；差异化／设计取舍与用户场景相关
- [ ] 主报告、体验材料和附录能互相定位；未完成项有下一步
