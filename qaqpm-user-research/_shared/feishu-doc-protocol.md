# QAQPM · 飞书文档交付协议

> 当项目文档落在**飞书知识库 / 云文档**时遵守本协议。本地-only 项目可跳过，但下列「表状」交付仍须有可审阅的表（MD/CSV 即可）。

## 1. 何时启用

用户明确要求「写到飞书」「Wiki 子文档」「飞书知识库」或项目索引以飞书 URL 为权威入口时启用。

## 2. 子文档与站序

| 站 | 飞书子文档标题（建议） | 本地镜像 |
|---|---|---|
| 索引 | `00 项目索引` | `00-项目索引.md` 或 `00 项目索引.md` |
| S1–S12 | 与站交付同名 | 同名 `.md` |
| 决策包 | 可嵌在索引或独立页 | `共享决策包.md` |

- 在父节点下**创建子文档**，不要把全站揉进一篇长文（除非用户只要单页摘要）。
- 发布后回写 `发布材料/published-nodes.json`（或等价）：`key → node_token / document_id / url`。

## 3. 必须用飞书多维表格的表

**规则（硬）：项目文档采用飞书存储时，下列权威载体 = 飞书多维表格（Bitables），禁止只用普通飞书文档里的 Markdown 表充当。**

定性长文（问题卡、立项报告、PRD 正文、竞品分析叙事与对照、技术链路 HTML 等）仍用普通文档/页面；**竞品不强制、也不默认进多维表**。

### 3.1 需求池（S3）— 硬

| 项 | 要求 |
|---|---|
| 创建 | 在同一 Wiki 空间下建「需求池」多维表（或 Base）；索引页与 `03 需求池` 文档内放入口链接 |
| 字段 | 至少覆盖课件字段 + 证据增强：ID、能力项、痛点/目标、建设方向、来源、提出方、状态、描述/PRD、证据编号、证据强度、假设标签、候选优先级、痛点 ID、验收题号、备注 |
| 视图 | 至少：全部需求、P0/首版候选、后续规划（名称可本地化） |
| 本地镜像 | **必须**另有 `03-需求池.md`（或同名）含**只读全表镜像**或可导出的 CSV/MD 表；行数 ≥ 多维表有效记录数 |
| 冲突 | 以评审后的双写为准；未对账前不得宣称 S3 通过 |

### 3.2 评测集 / 黄金集（S7）— 硬

| 项 | 要求 |
|---|---|
| 创建 | 建「评测集」或「黄金集」多维表；索引页与 `07 评测设计与测试集` 文档内放入口链接 |
| 字段 | 至少：题号、题型（正常/边界/红线/反例）、场景标签、输入摘要、预期要点、适用维度、来源（真实/专家/AI）、状态（草稿/冻结）、门禁版本、备注；RAG/Agent 项目追加检索可核对字段 / 过程检查点 |
| 视图 | 至少：全部题目、红线题、本轮门禁冻结集（名称可本地化） |
| 本地镜像 | **必须**另有 `eval/` 下索引（如 `eval/gold-v*.md` / CSV）全字段镜像；行数 ≥ 表内有效记录；单题细节可仍用 `eval-item` 文件，但索引权威在多维表 |
| 冲突 | 以评审后的双写为准；未对账前不得宣称 S7 黄金集 v0 已就绪；S11 跑分以冻结视图为准 |

### 3.3 Bad case / 缺陷回流表（S10 起，S12 续写）— 硬

| 项 | 要求 |
|---|---|
| 创建 | 建「Bad case」多维表；`10 开发推进` / `12 上线观察` 文档内放入口链接 |
| 字段 | 至少：ID、发现站（S10/S11/S12）、现象摘要、复现步骤或输入、期望 vs 实际、归因（产品/模型/数据/提示/工程）、严重度、状态、是否回写评测题（题号）、关联需求 ID、负责人、备注 |
| 视图 | 至少：未关闭、本迭代新增、已回写评测集 |
| 本地镜像 | `10-开发推进记录.md` 内索引表或 `dev/bad-cases.md` / CSV；行数对齐 |
| 冲突 | 未对账前不得宣称「bad case 已闭环」；回写评测集须同步更新 3.2 表 |

### 3.4 功能验收用例表（S11，≠ AI 评测集）— 硬

| 项 | 要求 |
|---|---|
| 创建 | 建「功能验收用例」多维表（与 3.2 评测集**分表**，禁止混一张大杂烩） |
| 字段 | 至少：用例 ID、模块/场景、前置条件、步骤摘要、期望结果、实际结果、状态（未测/通过/失败/阻塞）、阻塞原因、关联需求 ID、执行人、执行日期、备注 |
| 视图 | 至少：本轮必测、失败与阻塞、全量 |
| 本地镜像 | `11-验收与评测报告.md` 功能测试表或 `qa/func-cases.md` / CSV |
| 冲突 | 功能用例表 ≠ 黄金集；门禁里的 AI 分数仍以 3.2 冻结视图为准 |

普通飞书文档里贴一张 Markdown 表**不满足** 3.1–3.4；多维表格才是对应载体。

## 4. 双写与回读

1. 先写本地 MD（或先写多维表，再立刻镜像）→ 再写入飞书。  
2. 写入后 `docs +fetch` / Base 读回：核对标题、关键表行数、链接、【事实｜推断｜待确认】未丢。  
3. CLI 文件路径须落在允许根（如 `/tmp`、cwd）；大内容用 `@file`。  
4. 交付报告写清：飞书 URL、本地路径、**各多维表 URL**（需求池 / 评测集 / Bad case / 功能验收用例）、未同步项。

## 5. 自检（飞书模式）

- [ ] 子文档按站创建且索引可点开  
- [ ] **需求池为多维表格**，且有全部 / P0 / 后续视图；本地 `03` 镜像对齐  
- [ ] **评测集为多维表格**，且有全部 / 红线 / 门禁冻结视图；本地 `eval/` 镜像对齐  
- [ ] **Bad case 为多维表格**（进入 S10 后）；本地镜像对齐  
- [ ] **功能验收用例为多维表格**（进入 S11 时），且与评测集分表  
- [ ] 竞品分析仍为文档（不做多维表硬规则）  
- [ ] 共享决策包非空壳；未冻则索引标红  
- [ ] 回读完成，未把「写入成功」当成「内容正确」
