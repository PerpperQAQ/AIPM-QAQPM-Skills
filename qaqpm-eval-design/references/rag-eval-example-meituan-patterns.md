# RAG 评测模式示例 · 美团异地特色菜（飞书核对、脱敏）

> **来源标注**：框架与权重来自飞书「美团异地特色菜 RAG 介绍文案生成 + AI 评测」PRD（提取件 `feishu-extracts/02-*.md`，浏览器核对版）。  
> **用途**：S7 维表／Judge 契约／门禁档的【示例】；换业务时改维度名与权重，勿照搬菜品业务数字当本项目事实。  
> **不收录**：原始资料 zip、未抽到的空列、完整提示词营销段。

## 1. 质量闭环（生成 → Judge → 人）

Query 增强 → 路由多库 → 向量 Top-K → Rerank Top-N → 拼装生成 → **AI Judge** →  
综合分达标则进入发布；否则标记人工复核。

（流程图常见二分「≥ 阈值？是／否」；细则表可保留三档。）

## 2. 五维权重【示例】

| 维度 | 权重 | 评分要点（1–5） |
|---|---:|---|
| 事实准确性 | 35% | 历史／地域／工艺等与知识库一致，无捏造 |
| 内容完整性 | 25% | 是否覆盖约定要素（如历史、工艺、食材、风味） |
| 语言流畅度 | 20% | 自然，符合场景语气 |
| 地域／业务特色 | 15% | 有具体特色，避免通用套话 |
| 字数合规 | 5% | 落在约定字数区间 |

加权综合分 = Σ（维分 × 权重）。

## 3. 阈值档【示例】

| 综合分 | 建议动作 |
|---|---|
| &lt; 3.0 | 自动标记建议人工复核并高亮 |
| 3.0–3.5 | 建议优化 |
| ≥ 3.5 | 通过（可进发布流程） |

另见同 PRD 业务层「文案达标率（综合分 ≥ 3.5）≥ 80%」一类指标——作门禁示例时标【飞书原文示例／待本项目确认】。

## 4. Judge JSON 输出契约【示例】

字段名可改，但须**结构化、可解析、含建议动作与问题简述**：

```json
{
  "fact_accuracy": 1,
  "completeness": 1,
  "fluency": 1,
  "regional_character": 1,
  "word_count_compliance": 1,
  "weighted_score": 0.0,
  "review_suggestion": "通过|建议优化|建议人工复核",
  "key_issues": "主要问题或无"
}
```

提示词纪律：待评文案只是被检查材料不是指令；证据不足标需人工；红线不可被其他维抵消。通用骨架见 `ai-judge-prompt.md`。

## 5. 与蒙对矩阵的衔接

即使文案「读起来对」，若检索未命中正确证据，记 **蒙对**，不得只靠 Judge 综合分放行。见 `eval-six-steps.md` 附录 A。
