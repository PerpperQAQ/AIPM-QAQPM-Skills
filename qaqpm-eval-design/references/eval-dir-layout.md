# eval/ 目录约定（S7）

```
eval/
├── README.md                 # 本项目评测说明与版本
├── rubric.md                 # 标注/评分规范（链 07）
├── gold/
│   └── v0/                   # 黄金集 v0
│       ├── manifest.csv      # 题号,题型,路径,维度
│       └── items/            # 每题一个 md/json
├── runs/                     # S11/S10 跑分记录
│   └── YYYYMMDD-HHMM/
│       ├── scores.csv
│       └── notes.md
└── badcases/                 # 从线上/验收回流
```

`07-评测设计与测试集.md` 必须写明 `gold_set_v0_path`。

## 开发与验收复用

S9/S10/S11 共用 `gold/` 的版本与 `runs/`，按站点和目的标识跑次，不复制独立题库。每个跑次在 `notes.md` 或运行清单中记录代码/未提交改动快照、模型/Prompt/相关配置、环境、题集版本、评分规范、标准版本、题号覆盖、运行命令、结果与原始证据路径。原始截图/工程日志可以位于开发仓库产品目录，只存引用。

线上新案例先放 `eval/online/YYYYMMDD/` 并关联现有 Bad case；S7评审后升入新版本 `gold/`。旧题集和旧跑次保留，不用新标准改写旧分数。飞书模式仍以冻结视图及全字段本地镜像对账，工程原始证据不取代题集权威。

## 专题对象与运行Case扩展

保留原目录与ID，按项目需要追加：

```text
eval/
  objects.md                 # 对象与四类材料映射，可合入07
  rubrics/                   # 多对象需独立标准时使用；原rubric.md可保留索引
  gold/<version>/            # 同源样本；标目的、适用对象和覆盖
  runs/<run_id>/
    cases.csv                # 每对象/候选/样本/尝试的执行、输出与判定
    scores.csv               # 可作为cases的评分视图或独立关联分项
    notes.md                 # 版本、配置、环境、范围、分母与未运行原因
```

模板见[运行记录](../templates/测试Case记录.md)。已有等价字段与存储无需搬迁；明确唯一记录位置与引用。早期验证同样写真实跑次，设计阶段不创建假执行；后续标准变更不覆盖旧分数。
