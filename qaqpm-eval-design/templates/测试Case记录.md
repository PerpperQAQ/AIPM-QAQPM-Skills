## 2. 逐条记录

逻辑唯一键为 `run_id + object_id + candidate_id + case_id + attempt_id`。沿用已有标识时保持同等可区分性。

| Case／对象／候选／尝试 | 实际输入与前置 | 实际输出／产物／轨迹 | 执行状态／错误 | 链路判定 | 结果判定／分项评分 | 耗时／成本 | 证据／Bad case |
|---|---|---|---|---|---|---|---|
| | | | not_run | | | | |

执行状态可用not_run、running、succeeded、failed、timeout、cancelled、blocked、submission_unknown；按实际系统映射。`succeeded`仅表示执行返回，质量仍按标准判定。没有发生的执行不能填时间、输出或成功结果。

## 3. 字段解释

| 字段族 | 要求 |
|---|---|
| 对象／候选／版本 | 明确评的是模型、组件、Agent、RAG系统还是具体生成／识别任务 |
| input_ref／expected_ref | 原始输入或素材、前置条件、题集预期；不能把事后修改当原输入 |
| output_ref／trace_ref／evidence_ref | 可访问产物、可观察工具与节点状态、原始输出；无产物留空并写原因 |
| score_ref／judge | 分项打分、评分理由、评审方式及裁判版本 |
| latency_ms／cost／cost_unit | 测量范围、币种或计量单位、费用来自实测或估算；估算标明 |
| metric_eligibility_ref | 各指标的分母与不可评分规则引用；不得事后把失败随意排除 |
| 专用字段 | 见下表，允许放关联JSON、附表或Base关联记录 |

## 4. 对象专用记录

| 对象 | 追加证据 |
|---|---|
| Agent | 节点序列、工具与参数、关键状态、失败位置、恢复／人工介入、任务是否完成 |
| Embedding／检索／Rerank | 语料／索引版本、预期相关项、候选集、实际召回与排序、Top-K与过滤规则 |
| RAG系统 | Query、实际召回、传入上下文、最终答案和引用；分开检索与回答判定 |
| 文本／图像／视频／音频生成或编辑 | 原素材、Prompt与参数、采样设置、产物与版本、适用的主观／客观评分 |
| ASR／OCR等识别 | 原始媒体、参考转写／标注、预处理规则、实际识别与错误位置 |
