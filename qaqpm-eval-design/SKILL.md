# QAQPM-评测与测试集（S7）

笔记锚点：day17 评测六步与四时点；w4d2；架构 §5（设计早、执行晚）；飞书美团评测节／国华 3.8 defer。

## 1. 何时用 / 何时不用
**用**：S6通过或条件通过后的正式评测设计；也接受S5为关键可行性假设调用最小设计。早期调用设`evaluation_purpose: feasibility`，明确返回S5/S6，只完成当前实验需要的标准、样本、运行结构与判定，不自动标整站或正式准入材料已完成。
**不用**：替代实际运行与验收。选型／早期实验执行交S9，开发回归交S10，正式准入交S11；均沿用本站标准与题集。

## 2. 上游依赖
正式设计读取S6档位与质量门槛、S5核心假设、S1 AI适用性及已有专题需求。早期可行性设计以S5假设、业务样本与本次决定为输入，不要求先有S6或S8终稿。先读[_shared/ai-document-protocol.md](_shared/ai-document-protocol.md)；飞书输出时再读飞书协议。

## 3. 目标与通过线
完成六步中的设计侧：①目标 ②标准 ③评测集结构（及黄金集 v0）④打分方式约定 ⑤报告模板骨架 ⑥归因框架。早期单项验证只完成当前假设所需的设计，注明样本版本、未覆盖项和返回站，不把下文完整设计清单机械变成前置条件。  
覆盖：维度菜单、GSB／裁判校准、RAG 检索+回答+蒙对、Agent 过程+结果、报告四行。  
**不**在本站伪造已跑分数。PRD 验收必须能引用本站门禁。

### 存储形态（硬规则）

| 模式 | 权威载体 | 本地必有 |
|---|---|---|
| 本地-only | `eval/` 索引 + 单题文件 | `07-评测设计与测试集.md` + `eval/` |
| **飞书存储** | **飞书多维表格（评测集/黄金集）** | `07` 文档 + `eval/` **全字段只读镜像**（行数 ≥ 表内有效记录） |

- 用户采用飞书存文档时：**必须**用多维表格存评测集，禁止只用普通飞书文档里的 Markdown 表充当题库。
- 多维表至少三个视图：全部题目、红线题、本轮门禁冻结集。
- 字段至少：题号、题型、场景标签、输入摘要、预期要点、适用维度、来源、状态、门禁版本、备注；（RAG/Agent 追加专用列）。
- `07` 写清多维表 URL、镜像路径、「设计≠已跑分」。
- 无本地镜像或行数对不齐 → **S7 自检不通过**（不得宣称黄金集 v0 就绪）。

## 4. 引导流程
| Phase | 产出 |
|---|---|
| P0 | 评测支持的决定、对象及目的（feasibility/selection/iteration/acceptance/online）；记录来源／返回站与storage_mode |
| P1 | 依据对象与业务从维度菜单选必要维度并排序；早期实验只覆盖相应假设与关键失败条件 |
| P2 | 形容词→可观察条件；分档+样例；人人一致性计划 |
| P3 | 题型：正常/边界/红线/反例；题源：真实>专家>AI补 |
| P4 | 落盘 `eval/`；**飞书模式**：创建/更新评测集多维表与视图 → 写本地镜像 → 回读对账；RAG/Agent 附加字段若需要 |
| P5 | 打分约定（是非／1-5／GSB）+ AI 裁判校准计划 |
| P6 | 门禁草案；报告四行骨架；归因框架 |
| P7 | 更新07与同源评测材料；正式设计通常交S8，早期设计交S9执行后回S5/S6；单项请求返回原任务 |

## 评测对象与四类材料

先用[评测对象与材料映射](templates/评测对象与材料映射.md)列实际模型、Agent、RAG组件／系统、生成／识别任务；按需读[对象配置](references/eval-object-profiles.md)。未采用组件／模态不生成材料，共享模型与样本通过ID引用。

- [评测标准](templates/评测标准.md)：可与rubric或原评测方案合订。
- 原评测集与单题模板：保存样本定义、来源及预期；实际输出进入runs。
- [测试Case记录](templates/测试Case记录.md)及[CSV字段](templates/测试Case记录.csv)：保留对象、候选、尝试、版本、输出、失败和原始证据。
- 原评测报告：选型／迭代与S11准入共用分析方法，实际结果执行后填写。

“四件套”描述材料职责，原《评测方案》《评测集》《评测报告》继续兼容。早期样本冻结其版本和覆盖范围，不把小样本自动标完整黄金集；后续复用并补充覆盖。

## 6. 输出大纲
完整设计必填：存储形态（local / feishu + 多维表 URL）、目标、维度细则、题型覆盖、黄金集 v0 路径（飞书模式下＝本地镜像路径）、打分角色、门禁草案、报告四行骨架、局限。早期验证可合订为一份最小设计，包含目的、对象、判定、样本版本、运行记录方式、执行条件与返回站。  
选填：AI 裁判校准计划、RAG 蒙对约定、Agent 过程维。

## 7. 证据规则
样例与阈值无业务确认则【待确认】；不编造历史准确率。美团／国华数字仅作结构示例并标注来源。

## 8. HTML
完整设计可用`reports/07-评测设计.html`展示维度、题型分布和门禁。早期验证或单项材料按交付需要生成；飞书多维表承担在线筛选，不强制另做题库HTML。

## 开发流程复用

S9 选型、S10 Agent 初验/回归、S11 正式评测、S12 线上验证均引用本站同一套标准；工作流见 [_shared/development-kit-protocol.md](_shared/development-kit-protocol.md)。将 `gate_version`、`dataset_version`、`rubric_version` 与真实路径写入交接，子集记录题号和覆盖范围；没有标准时先定草案，不能由开发脚本自行判“效果好”。

沿用 `eval/gold/` 与 `eval/runs/`，不在流程仓库另建一套独立黄金集。真实冒烟只证明相应链路，不能替代冻结集评测。开发中调整标准回本站留变更记录；S12 新失败先入 `eval/online/`，评审后加入新版本黄金集，不覆盖旧跑分依据。

## 10. 交接区
`eval_goal`, `dimensions`, `gold_set_v0_path`, `gate_rules_draft`, `judge_prompt_path`, `storage_mode`, `eval_bitable_url`, `eval_md_mirror_path`；`next_station`依本轮任务填写：正式设计通常S8，早期设计交S9执行后回S5/S6，单项请求返回原任务。未建路径留空并注明待创建。

## 11. 回流
指标大改 → 停 S8/S11 回本站；发现题集不覆盖真实失败 → 增补 eval（及飞书多维表）并通知 S11/S12；飞书表与 MD 冲突未评审 → 先对账再进 S8。

交接按需增`evaluation_purpose`、`eval_object_refs`、`run_record_template_path`、`return_station`。Agent链路与结果、RAG检索与回答、AIGC各任务与整体流程分别判定；失败和无产物运行不能从记录中删除。
