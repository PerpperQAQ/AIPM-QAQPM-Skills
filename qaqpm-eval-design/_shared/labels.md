# QAQPM 证据标签（全站强制）

> 来源：day11 证据三分法；AIPM 完整流程框架；teardown Skill。  
> 所有子 Skill 的结论句、表格单元格、HTML 报告条目，**必须**带且仅带下列之一。

## 标签定义

| 标签 | 含义 | 必须附上 | 禁止 |
|---|---|---|---|
| 【事实】 | 页面、材料、访谈原话、日志里直接可见或可核对 | 截图编号 / 原文链接 / 引文 / 数据口径与时间 | 把宣传文案、AI 口述、未经核对的搜索结果当事实 |
| 【推断】 | 由 ≥1 条事实合理推出 | 「因为 A、B，所以……」 | 无依据的常识补全；把推断写成已验证结论 |
| 【待确认】 | 查不到或未验证，只是假设/猜测 | 怎么核实（去哪看、跑什么测试、问谁） | 用待确认数字支撑立项「通过」档 |

## 使用纪律

1. **无来源不编造**：模型名、单价、用户量、转化率、市场规模——查不到就【待确认】，宁缺勿编。
2. **相关 ≠ 因果**：相关数据可引用，必须标性质与口径（day13 高德案例纪律）。
3. **收益测算 ≠ 上线成果**：测算数字写清「原文测算 / 未财务复核」。
4. **Agent 说「已完成」→ 回页面看东西是否真的生成**（day11）。
5. **AI 说「官方写了」→ 打开原文核对**（day11）。
6. 用户原话与「我们推导的解决方案」必须分行；矛盾说法回场景，不挑支持己方的一句（day13）。

## HTML / 报告映射

- `fact` → 【事实】色标（建议绿/实线）
- `infer` → 【推断】色标（建议琥珀）
- `tbd` → 【待确认】色标（建议灰/虚线）
- 报告顶部提供筛选：全部 / 隐藏推断 / 只看事实（对齐 teardown `report-template.html`）


## 标签别名（课件 ↔ QAQPM）

| 课件常用 | QAQPM 标签 | 说明 |
|---|---|---|
| 页面事实 | 【事实】 | 页面／材料直接可见 |
| 合理推断 | 【推断】 | 须写「因为…所以…」 |
| 尚未确认 | 【待确认】 | 须写核实方式 |

拆解、竞品、技术链路 HTML 三色标与上表一致。写「页面事实」时可在括号注明（＝【事实】），但入库统一用三标签。

## 官方记载 ≠ 本项目已验证（反例）

| 说法 | 正确标签 | 错误写法 |
|---|---|---|
| 官方文档写「支持多用户」 | 【事实：文档记载】 | 【事实】我们已具备多用户 |
| 候选底座 README 宣称会话恢复 | 【事实：材料可见】或【待确认：本环境未跑】 | 【事实】POC 已通过恢复 |
| 评测/POC 结果表尚无跑数 | 结果列 `not_run` + 【待确认】 | 「通过」「达标」无证据链接 |

评测与 POC：结果列出现「通过／失败」必须附证据路径或飞书记录链接；默认 `not_run`。
