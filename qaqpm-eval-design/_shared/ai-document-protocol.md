# AI 专题文档：S5 启动、持续完善

适用：Agent、RAG、AIGC 专题需求、组件选型与评测材料。完整性按实际能力与交付目标判断，不以固定文件数量判断。模板结构来源见 [document-template-sources.md](document-template-sources.md)。

## 1. 阶段与成熟度

| 位置 | 负责的决定与材料 | 通过依据 |
|---|---|---|
| S5 MVP方案与范围 | 能力适用清单、专题需求首稿、核心链路、范围、关键假设与验证计划 | MVP 做什么、怎样完成任务、未知事项与验证方法说清楚；允许技术候选未定 |
| S6 立项 | 根据范围、资源、风险与已有验证决定投入 | 条件立项绑定具体待证事项与停止条件 |
| S7 评测设计 | 标准、题集、运行 Case 结构、评分与分析方法 | 验证目的与对象明确；材料可执行、版本可引用 |
| S9 PoC与选型 | 实际比较模型／组件／方案，记录配置、运行与结论 | 仅对已测对象与范围下结论，回写 S5/S6/S8 |
| S8 需求细化与开发交接 | 完善同一份专题文档的行为、接口、数据、权限、状态和验收引用 | 开发与测试可执行；未决项、冻结状态如实保留 |
| S10/S11/S12 | 实现、回归、正式验收、上线观察与回流 | 版本、运行、产物和业务结果的真实证据 |

- 文档成熟度用 `mvp_draft`（MVP草案）或 `development_ready`（开发交接版）；另写草稿／待评审／已评审／受阻／已过期等状态。已有状态命名可沿用并说明映射。
- 成熟度不代表当前站点。已有PRD的单项讨论稿可沿用项目的草稿命名并注明“尚未开发就绪”，无需改称MVP项目或退回S5。
- “文档已评审”“模型已选择”“链路已验证”“产品已验收”分别记录。完成模板不等于完成验证。
- S5 可调用 S7 的最小可行性评测设计，再由 S9 在已授权的环境和预算中实际验证；这是同一套标准与记录的早期使用，不把整个 S7/S9 自动标为完成。
- 早期验证设置 `evaluation_purpose: feasibility`、记录 `return_station: S5` 或 `S6`；正式选型、迭代、验收、线上观察分别使用 `selection`、`iteration`、`acceptance`、`online`。编号表示职责，允许交错推进。
- S8 沿用 S5 文件和能力 ID，补充而不复制第二套正文；重大范围变化回 S5。最终 PRD 仍执行原有决策冻结及 S7 引用要求。

## 2. 条件路由

| 实际需求 | 调用 | 判断依据 |
|---|---|---|
| 动态选择工具、任务规划、多步自主判断或多 Agent 协作 | `qaqpm-agent-requirements` | 写产品中的 Agent；给编码助手的开发约定仍归 S8 |
| 基于外部知识检索并组织答案／生成内容 | `qaqpm-rag-requirements` | 知识来源、更新、权限、检索与生成关系 |
| 文本、图像、视频、音频等生成或编辑 | `qaqpm-aigc-requirements` | 创作任务、素材、控制、产物、修改与采用 |
| 固定步骤的确定性工作流 | 按功能需求记录；确有上述能力时组合专题 | 不为了凑 Agent 数量拆角色 |
| 仅 ASR/OCR 等识别任务 | 功能需求＋S7相应任务评测配置 | 可处于多模态产品中，任务类型仍是识别 |
| 不涉及 AI | 保留范围与功能需求 | 不创建 AI 专题、模型选择或评测材料 |

多个能力组合时共享背景、用户、业务规则、工具、模型与数据定义，通过 ID／路径引用。相同模型可共用选型比较，但各任务适用性及系统效果分别解释。未用 Rerank、GraphRAG、视频等能力，标不适用和理由即可。

## 3. 文件与引用

默认在项目已有文档根下维护，已有路径优先；小项目可以合订，不强制按文件拆分。

```text
ai/
  00-AI能力与文档清单.md
  agent/                 # 需求、节点协作、工具、Prompt与上下文
  rag/                   # 需求架构、来源维护、处理入库、检索生成
  aigc/                  # 需求、任务模态、生成编辑、素材参数
```

S5 主范围和 S8 PRD 引用这些文件。`08-Agent规范/` 保持历史路径兼容、展示名“开发与接口约定”；它不是产品 Agent 需求文件。选型复用 `09`，评测复用 `eval/`，工程任务复用已绑定开发仓库。

每个文档至少记录：能力 ID、关联需求／痛点、成熟度、版本与状态、事实来源、当前已决／待证、相关文档和评测对象、接手后第一步。清单中声明的已生成路径必须真实存在；计划路径标“待创建”，不宣称完成。

## 4. 按交付范围使用模板

- 新建 MVP：先确定能力与范围，再为适用能力写首稿。S5 首稿中实现参数可以待选，但用户任务、核心输入输出、主要链路、关键风险与验证动作不能只剩空标题。
- 开发交接：补字段结构、转换条件、权限、错误处理、依赖和验收引用；无资料的关键项保留待确认，不能自动用实例补齐。
- 单份文档／已有项目：只更新所请求材料和直接相关引用；不因调用专题重走 S1–S12、强制新建立项报告或重写背景。
- 模板里的待填项和示例是编写提示。交付时填成项目内容、明确待确认及解决方式，或写不适用理由；删去与任务无关的章节。
- 完整模板不意味着强制等待用户逐章批准；继承已确认信息，必要问题集中询问，可独立推进的部分继续完成。

## 5. 评测四类材料

| 材料 | 内容 | 维护方式 |
|---|---|---|
| 标准 | 对象、任务、维度、评分、门槛与分母 | S7 rubric及对象配置 |
| 题集 | 样本、前置、输入、预期、来源及适用对象 | 同源 gold，可按对象筛选 |
| 运行 Case | 实际配置、输入输出、状态、评分与原始证据 | runs；一个样本可有多个候选与尝试 |
| 指标与分析 | 汇总、分类差异、失败归因、选择或改进决定 | S9中期／S11正式报告，引用跑次 |

现有《评测方案》《评测集》《评测报告》继续使用；标准在方案／rubric 中，运行 Case 作为明确配套。样本定义不混写成运行结果；模型、Agent、RAG组件、RAG系统和各生成／识别任务区分对象。失败、超时、无产物运行都保留，评分不可用时说明原因，不能删掉后再计算成功率。

## 6. 模板来源与适配

优先采用用户指定合集对应结构，按 [document-template-sources.md](document-template-sources.md) 记录来源 ID。原文中的模型、价格、业务目标、评分权重和效果数字仅为实例；当前项目需另定并验证。来源文档内部矛盾先标明并修正结构，不沿用成产品约束。不得将课堂计数当作必须生成的文件数量。

飞书模式采用 [feishu-doc-protocol.md](feishu-doc-protocol.md)：长文与表状记录分别使用合适载体，原四表继续复用。维护索引中的逻辑 ID、实际文档 URL 与本地镜像，不依赖文件名猜测对象。
