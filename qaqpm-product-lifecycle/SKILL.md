# QAQPM-产品全流程（总控）

> **本轮增量 Changelog 2026-10-30**：`_shared/html-report-shell.md` 新增「HTML 设计限制」硬规，默认浅色网格纸 + 橙强调色。  
> **Changelog 2026-10-29**：00 强制销售陪练六节开篇；Phase1 无决策表+决策一页纸不得宣称 S1–S6 齐；收尾对账 00/03/决策与 published-nodes；展示名去课件味；`_shared` 根为单一真相；产品包文风见 `_shared/product-doc-readability.md`。

**一句话**：需求＝用户没被解决的问题；立项＝拿证据换资源；做完 Demo ≠ 做完需求分析。

## 1. 何时用 / 何时不用

**用**：用户要从想法/老板一句话推进到立项、评测、PRD、POC、开发、验收或上线；或询问「我卡在哪一站」。  
**不用**：纯简历/面试诊断；只要单次代码实现且无产品决策；只要拆某一竞品且明确说「只拆解」→ 仍可路由到 S6 拆解模块或 S4，但不必走满 12 站。

## 开发入口（先判断，优先于下文通用建档流程）

用户说“PRD 已定，开始开发”“继续开发 XX”或从 S9 进入实施时，路由 `$qaqpm-dev-track`，先读 [_shared/development-kit-protocol.md](_shared/development-kit-protocol.md)。S10 首次经确认拉取 `https://github.com/PerpperQAQ/QAQPMskill-idea-to-launch-kit.git`，续做复用绑定版本；总控不自行提前 clone，不把讨论方案或修改 Skill 当成开发触发。

主线：**产品 PRD → 固定技术选型 → 分阶段技术开发文档 → 后端可验证 → Agent 初验 → 前端可交互（Web 优先，其他端按需）→ 前后端联调 → 功能与 Agent 效果验收 → 部署/数据/登录/域名 → 埋点验证 → 线上效果、数据分析与用户反馈。** 详细映射见共享协议。

有现成 PRD/代码可以直接进入开发接入检查；缺评测标准补 S7，缺实施所需需求补 S8，关键技术未证实回 S9。不要为了直接开发补造 S1–S6 终稿，也不默认重走调研和立项。保留既有未决项与来源，不宣称前序站已通过。

直接开发/续做只更新相关索引摘要、开发记录、接入和证据引用；下文长对话立项建档、03与一页纸同根、分享 HTML 等要求在对应产品包交付时执行，不因每次代码修改重做全部材料。已有飞书交付约定仍在相应交付节点履行，缺同步如实报告。

总控镜像仓库阶段，不另设一套可独立推进的开发状态。S10→S11→S12 接续原仓库阶段；S11通过不是发布授权，仓库收尾也不等于用户价值验证。

## AI专题与单文档入口（优先于通用建档）

用户在规划MVP、梳理Agent/RAG/AIGC方案时，S5使用“方案与范围”模式，先读 [_shared/ai-document-protocol.md](_shared/ai-document-protocol.md)。S5启动专题首稿，S7/S9补验证依据，S8沿用原文档细化开发交接。三个专题是可复用能力，不增加阶段编号。

| 请求 | 路由 |
|---|---|
| 产品Agent任务、工具、协作、Prompt或上下文需求 | `$qaqpm-agent-requirements` |
| RAG需求、知识维护、入库或检索生成 | `$qaqpm-rag-requirements` |
| 生成编辑、素材参数、任务模态与产物需求 | `$qaqpm-aigc-requirements` |
| 已有项目只补某份功能／总体设计／埋点／看板／多语言等文档 | 路由S8相应模板，限定本轮范围 |

单专题或单文档请求直接处理该范围与相关引用，跳过全站建档、重建03／一页纸和整包HTML要求；不能借此宣称完整阶段已通过。既有飞书输出约定按本轮交付范围执行。

## 2. 上游依赖

**专项入口 · 核心技术难题梳理**：用户问「除了已知难点，还有哪些技术问题我必须懂」「哪些风险会改变架构或产品承诺」时，直接使用 `$qaqpm-tech-risk-review`。从当前项目的用户动作、失败场景和证据出发，交付优先难题、取舍、最小验证与自测情境。单独咨询到此交付，跳过下述建档与站序更新；若用户正在推进整站，再将结果交回当前站。

- 扫描项目根：`00-项目索引.md`、各 `0x-*.md`、`立项决策一页纸.md`、`research/`、`eval/`、`reports/`、文末交接区。  
- 读 `_shared/labels.md`、`handoff-schema.md`、`html-report-shell.md`、`research-methods.md`、`archify-tech-map.md`、`product-doc-readability.md`、**`feishu-doc-protocol.md`（飞书模式）**。  
- **`_shared` 单一真相**：开源仓库根 `_shared/` 为权威；改协议先改根再同步各 `qaqpm-*/_shared/`；禁止只改某一站副本。  
- 有则继承，**禁止重复问已确认事实**。

## 3. 本站目标与通过线

| 目标 | 通过线 |
|---|---|
| 定当前站与下一站 | 用户确认或默认建议被接受 |
| 维护索引与交接 | `00` 六节开篇完整；交接含「接手后第一步」 |
| 强制证据标签 | 子 Skill 产出无标签则打回；遵守密度规 |
| 长对话决策可扫 | 存在 `research/已确认决策表.md` **且**人类可读「立项决策一页纸」 |

## 4. 引导流程（Phase）

### Phase 0 开场（一次问清）
1. 新项目还是续做？  
2. 若续做：目录里已有哪些文档？你认为卡在哪？  
3. 本轮目标：只到立项 / 到评测集 / 到 PRD / 到 POC / 到上线？  
4. 文档落盘：本地-only 还是**飞书知识库**？（飞书 → 启用 feishu-doc-protocol；**四表必须用多维表格**；竞品仍用文档）

### Phase 1 扫描与建议（fail-closed）
- 无索引：先判断上文开发入口；只有新产品问题定义/立项任务才创建完整产品包并建议 S1（或双入口见下）。  
- 有索引 → 读 `current_station` 与 blockers。  
- **来自长对话 / 多线程 / 多会话**：  
  1. 抽取或更新 `research/已确认决策表.md`（列：收敛结论｜【事实｜推断｜待确认】｜来源｜写入站）。  
  2. **强制**产出／更新人类可读 **`立项决策一页纸.md`**（已决｜仍要证明；可 `frozen=false` 红字）——不只 YAML／研究表。  
  3. 缺**执行位置、底座、不做清单、访问入口**任一项 → 标 blockers。  
  4. **无决策表，或缺上述字段，或无一页纸 → 禁止宣称 S1–S6 文档包已齐**；允许继续补洞，但不得在索引写「S1–S6 齐／可进开发」。  
- 给出「建议下一站」+ 备选，用户可改选。

### Phase 2 路由
调用对应 `qaqpm-*` 子 Skill；总控不代替写长稿。飞书模式：子 Skill 交付后按协议双写并回读。产品包文风走 `product-doc-readability.md`，**不**套 `human-writing` 散文硬禁令。

### Phase 3 收尾（权威对账）
1. 更新 `00-项目索引.md`（六节开篇；决策档位；**立项决策一页纸冻结红绿灯**；飞书／多维表链接）。  
2. **声明唯一权威根**（本地路径或飞书父节点）；`00` ↔ `published-nodes`（若有）↔ 飞书 URL **对账**。  
3. **`03-需求池` 与立项决策一页纸必须同时存在于权威根**；冲突未评审不得标通过。  
4. 确认交接区有人话「接手后第一步」，YAML 无同质复读。  
5. 飞书／分享项目：检查 `reports/00-项目全景.html` 与 `reports/立项决策一页纸.html` 存在性。  
6. 问继续 / 停 / 回流。

### 特殊分支（必须遵守）
| 分支 | 行为 |
|---|---|
| 双入口 | 允许「先 S2 后 S1」或「先 S1 后 S2」；**S6 前两者齐** |
| 证据为空 | 先 S2 或与 S1 交错 |
| 技术风险高 | S5调用S7最小可行性评测设计，再由S9在已授权环境和预算中验证；保留真实结果及覆盖限制，回S5/S6决策 |
| S6 通过后 | 默认S7完善标准与题集，S8细化需求；必要时S9先验证再回写S8，沿用S5首稿和已有早期材料 |
| 只要拆解某产品 | S6 内拆解模块（或 S4 复用） |
| 要 HTML | `_shared/html-report-shell.md`；分享项目强制 00＋决策 HTML |
| 飞书存储 | **S3/S7/S10/S11 四表＝多维表格** + 本地镜像；竞品不用多维表 |

### `00-项目索引.md` 强制六节（销售陪练语义）

站序表**下沉**到第六节或附录；开篇禁止只有站序导航。

```markdown
# <项目短名> · 项目全景

## 1. 一眼看懂
- 一句话产品／要解决的事
- 当前状态黄条（如：条件立项 · 决策未冻 · 卡在访问入口）
- 本轮目标

## 2. 证据边界（红条）
> 相关 ≠ 因果；外部经验 ≠ 本团队已量化；测算 ≠ 已上线；官方记载 ≠ 本项目已验证。
（项目特有边界补在此）

## 3. 怎么工作
- 权威根路径／飞书父节点
- 存储：local | feishu（四表链接）
- 读者怎么用本包（先读一页纸 → 再下钻）

## 4. 已决 vs 待证
| 已决定 | 仍要证明／未冻 |
|---|---|
| … | … |
（或链到立项决策一页纸；frozen=false 时本节顶部红字）

## 5. 交接路径
- **接手后第一步**：…
- 建议下一站／blockers

## 6. 站序与文档清单（下沉）
- 当前站／建议下一站
- 文档清单（路径 · 展示名 · 状态 · 更新时间）
- HTML 清单 · published-nodes 对账
- 开放问题（含架构取舍是否已写入 05/06/09）
```

## 6. 输出文档大纲

总控直接产出/更新：`00-项目索引.md`、`立项决策一页纸.md`、必要时 `research/已确认决策表.md`。其余由子 Skill 产出。

## 7. 证据与标签规则

全站强制 `_shared/labels.md`（含密度规与「官方记载 ≠ 本项目已验证」）。总控抽检：无标签的关键结论 → 打回；逐句堆标 → 按密度规打回。

## 8. HTML 输出约定

- 公共壳：`_shared/html-report-shell.md`  
- **飞书／分享：强制** `reports/00-项目全景.html` + `reports/立项决策一页纸.html`  
- 技术链路：`archify-tech-map.md` + S9  
- 拆解可视化：S6 `references/report-template.html`

## 9. 自检清单

- [ ] 已扫描目录与交接区，未重复盘问  
- [ ] `00` 含强制六节；站序不在开篇唯一位置  
- [ ] 长对话：已有决策表 **且** 立项决策一页纸；缺字段未宣称 S1–S6 齐  
- [ ] 权威根已声明；00↔published-nodes↔飞书已对账；03 与一页纸同根  
- [ ] 建议站与返回站理由说清；早期验证和正式阶段完成区分，S8开发交接引用适用S7标准；S5专题首稿未被复制成另一套  
- [ ] 飞书模式：四表多维＋镜像行数；无 Untitled；回读完成  
- [ ] 分享项目 HTML 两件套存在  
- [ ] 索引冻结状态与一页纸一致；未在总控展开长篇终稿  

## 10. 交接区字段

开发项目追加 `development_binding_path`、`kit_stage`、`delivery_target`、`evidence_refs`；值从仓库真实状态和接入记录镜像，不凭对话记忆推进。

见 `_shared/handoff-schema.md`。总控在索引中镜像 `current_station`、`decision_tier`、`blockers`、`html_reports`、`storage_mode`／飞书链接；正文必有「接手后第一步」。

## 11. 回流规则

| 信号 | 退回 |
|---|---|
| 差异化不成立 | S2/S4 |
| 技术不可行 | S5/S9→S6 |
| 资源不够 | S5 |
| 评测门禁改指标 | S7（S11 不重开设计） |
| 范围漂移 | S5/S8 |
| 权威根三件套冲突 | 停在总控对账，不进下一站 |

## 明确不做

- 不替代求职简历/面试诊断 Skill  
- S1–S6的文档规划不直接进入产品开发；核心可行性实验由S9在已授权范围内进行，实验结果回写S5/S6  
- 不把爬虫原声当成已验证用户需求  
- 不把「文档已写入飞书」当成「四表已用多维表／决策已冻结／内容正确」  
- 不把空壳 01–09 当成 S1–S6 已齐

AI专题交接按需镜像`ai_document_index_path`、`capability_ids`、`document_maturity`、`evaluation_purpose`与`return_station`；草稿齐全不代表选型、链路或产品验收完成。
