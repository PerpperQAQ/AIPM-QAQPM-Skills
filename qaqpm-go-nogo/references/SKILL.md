# AI 产品拆解：五层五问

**一句话**：从看得见的界面，倒推看不见的架构。拆的是 PM 的**决策**（为什么这样设计、给哪个用户设计），不是代码。传统产品交付工具，AI 产品交付结果。

**五层是一条链**：定位决定用户怎么用 → 用户层的每一步分给 AI 或人 → AI 做的步骤配上模型、算出成本 → 最后看哪些东西买不到。最终产出**一张架构图**，其余内容都是推导它的证据链。

## 执行流程

### Step 0　先定产品和目的（不清楚就问用户，一次问完）

- 输入是什么：产品名、链接、截图还是录屏？是网页、App 还是插件？
- 目的决定深度。"不可能无缘无故去拆一个产品"：

| 目的 | 拆哪些层 | 产出 |
|---|---|---|
| 日常练习 / 竞品调研 / 0→1 准备做同类 | 五层全拆，加竞品对比 | 完整拆解文档 |
| 1→N 加功能 / 只关心某个环节 | 只拆相关层（例如只加一个 Agent，就只拆 03） | 拆解文档节选 |
| 效果迭代 | 02 测评 + 03「它没做好的地方」 | 测评表 + 改进方案 |

### Step 1　取证

| 想知道什么 | 去哪看 |
|---|---|
| 给谁用、定位 | 官网标语、应用商店简介和评论、创始人访谈 / 播客、行业研报 |
| 收谁的钱 | 价格页、会员页、积分规则（**收谁的钱，就是给谁做的**） |
| 怎么用、背后流程 | **亲手跑**、公开演示视频、帮助中心、更新日志、任务回放 |
| 用什么模型 | 模型下拉框、更新日志、发布会、提交前的扣费提示 |
| 壁垒 | 隐私政策（数据怎么用）、接了哪些自家系统、官方访谈、GitHub 上的开源实现 |

- **亲手体验**：按下方「产品体验流程」执行，至少跑三轮，并填写体验记录表。
- **两条纪律**：01 Agent 或产品说「已完成」，要回页面看东西有没有真的生成；02 AI 或搜索结果说「官方写了」，要打开原文看。检索得到的模型名、价格、数字，回原页面核对过才能标【事实】。

### 产品体验流程（Step 1 的核心，细节见 `experience-guide.md`）

1. **选路径（按顺序）**：有浏览器操作类工具时，Agent 自己用网页版 → 只有 App 或用不了时，先搜公开演示视频和测评 → 仍缺的，给用户一份具体的截图清单。
2. **守边界**：登录、验证码、实名、付款都交给用户本人；Agent 不输入凭证、不替用户付款。只用免费额度，要花付费积分前先问用户。
3. **跑脚本（至少 3 轮 + 边界探测）**：① 模糊需求；② 具体需求；③ 故意异常（信息给不全 / 中途改主意 / 只改一部分 / 失败与退费）；④ 能力范围外、涉 IP 或敏感内容、换任务类型。
4. **按五步记录**：入口 / 输入 / 过程 / 输出 / 交付，每步截图编号。重点记过程文案（→ 提示词、Agent）、选择框（→ tool）、任务打勾（→ 状态管理）、推荐结果（→ RAG），以及等待时长、消耗的积分、成品质量。
5. **填体验记录表**：步骤 | 操作 | 页面表现 | 截图编号 | 耗时 | 消耗 | 反推线索 | 证据标签。结果喂给 02 的旅程图和测评打分、03 的反推、04 的成本。
6. **纪律**：任何"已完成 / 已生成 / 已退款"，都要回页面确认真的存在，才能标【事实】。

### Step 2　逐层拆（见下方「五层骨架」），每条结论都带证据标签

### Step 3　汇总：架构图 + PM 结论（可选：竞品逐层对比）

### Step 4　对照「自检清单」检查后交付。把所有【待确认】汇总成文末的「待核实清单」，每条写明怎么核实

### Step 5　生成可视化报告（可选，按需触发）

**触发**：拆解文档完成后用户想要可视化版本；或者用户直接说"生成 HTML / 可视化报告"并给了一份已有的拆解文档（这时跳过 Step 0–4）。

1. 通读拆解文档，按 `report-guide.md` 的 JSON 结构把内容映射进去。**只搬运文档里已有的结论和证据标签，不新增事实**；文档里没有的字段留空数组，对应模块会自动隐藏。
2. 用 `python3 fill_report.py data.json <产品名>-report.html` 生成。没有 Python 时，复制 `report-template.html`，只替换 `<script id="report-data" type="application/json">` 里的 JSON，其余代码一律不改。
3. 校验：JSON 能解析；用浏览器打开（有无头浏览器就截长图看一眼），确认没有控制台报错，五层导航、证据开关都能用。
4. 交付一个单文件 HTML（离线可开，可导出长截图或打印成 PDF），文件名用 `<产品名>-report.html`。

## 证据标签（每条结论必须带一个）

| 标签 | 含义 | 必须附上 |
|---|---|---|
| 【事实】 | 页面或材料里直接看得到 | 截图编号、原文链接或引文 |
| 【推断】 | 由几条事实推出来 | 依据（"因为 A、B，所以……"） |
| 【待确认】 | 查不到，只是猜测 | 怎么核实（去哪看、跑什么测试） |

**不编造**模型型号、价格、用户量和任何数字。查不到就写【待确认】，宁缺勿编。

## 五层骨架（顺序固定）

### 01 用户需求场景：用户为什么用它？
**小工具**：一句话公式 · B 端三个人　**产出**：一句话定位 + 商业判断

- **一句话公式**：一款给【谁】用的、在【什么场景】下、解决【什么问题】的【什么产品】。"谁"要细到能指导功能取舍：不写"电商商家"，写"只做黑人服装展示图的出海商家"。定位写宽了，后面全白做。
- **B 端三个人**：用的人、买单的人、验收的人，各自为什么用（买单的人权重更高）。如果是 C 端，就写清用户画像，并说明为什么体验是关键："稍微有一点不好用，立马就走"。
- **市场**：规模和趋势（引研报，注明来源和年份），为什么是现在。
- **竞争格局**分三层：工具 / 应用玩家、平台（渠道和分发）、模型厂商。再区分直接竞品和间接竞品。
- **差异化**：凭什么选它？比如垂直深度、交互形态（对话 / 画布 / 模板 / 嵌入）、交付导向。最后回到定位，解释"为什么这么设计"。
- **商业模式**：收谁的钱，怎么收（订阅、按量、积分、企业版、广告），免费额度和付费点设在哪。这部分要和 04 的成本对账。
- **种子用户**：第一批用户从哪来（内测排队、社区、KOL、案例展示）。

### 02 用户层：怎么用它把这件事做完？
**小工具**：正向五步 · 异常四条　**产出**：用户旅程图 + 测评打分

- **功能模块**：有哪些入口和模式，分别给哪类用户。
- **正向五步**：入口（从哪进）→ 输入（给它什么）→ 过程（看得见它在干什么吗）→ 输出（拿回什么）→ 交付（能直接用吗，还要改多少）。
- **异常四条**：信息给不全（会追问吗）· 失败（会告诉你吗，钱退吗）· 中途改主意（要从头来吗）· 不满意（能只改一部分吗）。
- **正向和逆向流程**：哪些节点能回退，回退到哪一步，靠什么实现。
- **它替代了以前什么工作流**：以前是谁、用什么工具、花多久；现在用户只剩哪几步。
- **亲手测评**：定测试场景 → 定维度和权重 → 打分 → 评级（模板见 `templates.md`）。
- **抠细节**：默认文案、@ 能引用什么、用选项代替填空、过程中有没有透出工具和 skill。每个细节都问一句"为什么这样做，为谁做"。

### 03 技术层：哪一步用 AI 做，哪一步人做，怎么做？
**小工具**：人机分工 · 确认点 · 下一步谁决定 · 单个 Agent　**产出**：技术流程图 + 人机分工表 + Agent 构成 + 单 Agent 拆解

1. **技术流程**：先还原"人原来怎么干"（业务流程和岗位），再逐步对照产品。
2. **人机分工表**：步骤 | AI 做 | 人做 | 确认点 | 为什么要人。需要人只有三个原因：**成本高 · 主观 · 担责**。判断标准是"错了，能不能在产品里改回来？"
3. **确认点四种放法**：动手前审方案 / 风险动作前停下来 / 事先给额度 / 用户自己调档。还要看用什么 UI 让人拍板（选项卡片通常好过开放式提问）。停太多用户嫌烦，停太少用户不敢交。
4. **下一步谁决定**：在 Chatbot → Workflow → Agent → 多 Agent 的光谱上定位，并写出外部信号作为依据（有没有计划、进度、子任务，在哪停下来问你；步骤跟着任务变，就是 Agent）。能穷举的用 Workflow，不能穷举才上 Agent。
5. **Agent 组成**：人类团队的分工怎么映射成 Agent（几个、什么角色、串行还是并行、有没有主 Agent），HITL 放在哪。说清为什么要拆成多个 Agent（任务复杂、单个 Agent 上下文会爆），以及代价（更贵；每步成功率 0.9，串五步只剩约 0.59）。
6. **单个 Agent**：挑核心的 1–2 个深拆，写清输入输出 / 任务 / 工具 / 规则。深度版按四步走：逻辑梳理 → 构成推导（ReAct 还是 Planner-Executor）→ 工具推导 → 提示词推导（见 `toolkit.md`）。
7. **横向机制**：全局上下文和状态管理（共享 PRD 字段、任务打勾、回退路由）；上下文工程（哪个 Agent 读写哪些字段）；违规和 IP 防护（在哪识别、怎么拦）。
8. **它没做好的地方**：现象 → 可能原因 → 解决方案（具体改提示词、工具还是状态机）。

### 04 模型层：每一步用什么模型，花多少钱？
**小工具**：每一步用什么模型 · 花多少钱　**产出**：模型清单 + 成本账

- **模型清单**：AI 做的每一步对上一个模型，写清四项：模态 / 模型和档位 / 自研还是外接 / 能不能换（换了会怎样）。每项附选择理由。
- **路由逻辑**：自动路由、按风格或场景匹配，还是让用户自己选。让用户选模型，说明这一步对成本敏感。
- **强模型还是聪明流程**：哪些环节必须靠强模型；哪些只是流程设计得聪明（拆细步骤、模板化），小模型或传统算法就够。
- **成本估算**：单任务成本 = Σ（每步调用次数 × 单价）× 重试系数 + 机器或第三方接口费用。再和单任务收费（扣的积分 × 积分单价）对比，算出毛利和免费用户的亏损。单价查不到就标【待确认】，只给公式和区间（模板见 `templates.md`）。
- **省钱手段**：分阶段确认，避免积分白扣；默认用中档模型；做缓存（KV cache）；用小模型或传统算法替代；批处理；用免费额度限流。

### 05 基础层：什么是别人买不到的，壁垒在哪里？
**小工具**：买得到 vs 买不到　**产出**：壁垒判断

- **先划掉买得到的**：模型、算力、通用工具和开源代码。
- **再列买不到的**：自有数据 · 业务接口和权限 · 用户和组织的上下文 · 攒下的方法（提示词、skill、工作流、知识库）。
- **数据内容和来源**：有哪些数据（用户资产、会话、风格库或知识库、skill、点赞点踩），从哪来，是否用于训练或调优（看隐私政策）。
- **数据飞轮**：用户资产、会话、风格库、Skill → badcase 库 → 评测集 → 调提示词、流程和 skill → 效果变好 → 用户更多。要回答的是：它会不会越用越强？
- **最厚的一层**：这家公司的精力最集中在哪一层？由此也能推出它要招什么样的 PM。

## 汇总

- **分层架构图**：五层（可以加商业行和市场行），框里写名词不写句子，每个框标证据标签。可以用 mermaid 画。
- **PM 结论**：
  - 体验设计、能力边界、信任设计，各写一两条。
  - Demo 到完整产品的五个差距：给谁用 · 出了错怎么办 · 稳不稳 · 账算不算得过来 · 凭什么选你。写出这款产品在每一项上是怎么补的。
  - 如果我来做：改什么、为什么改、怎么验证。
- **（可选）竞品逐层对比**：五层逐行对比，最后回到定位，解释差异从哪来。

## 反推技巧：看到什么 → 推出什么

| 看到 | 推出 |
|---|---|
| Agent 的岗位名（艺术总监、编剧……） | 原来的业务流程；为什么拆成多 Agent，为什么串行 |
| 过程文案、思考过程 | 系统提示词的要点 |
| 结构化选择框、固定 N 个选项 | 一个封装好的 tool（先想想不调工具时它会怎么展示） |
| 任务打勾、进度条 | 状态管理 |
| Agent 交接时传的参数或摘要 | 共享上下文（全局 PRD 字段） |
| 从大库里推荐前 N 个 | RAG 检索 + 排序 |
| 技能列表、场景模板 | Skill 库 |
| 让你选模型、提交前显示扣费 | 成本敏感点，以及确认点 |
| 需求模糊就追问，需求明确就直接跑 | 需求澄清分支 |
| 有计划和子任务，步骤随任务变 | Agent（而不是 Workflow） |
| 反复说同一句话、卡住不动 | 状态没更新，或工具调用失败 |
| 涉及 IP 或真人时多出一步 | 合规拦截节点 |

更多判断方法（自己搭一个复现、去 GitHub 搜、测边界）见 `toolkit.md`。

## 常见错误

1. 定位写得太宽（"需要生图的人"），后面全白做。
2. 只罗列界面上的功能，像普通用户一样，没讲出"为什么这样设计、为谁设计"。
3. 用工程师视角拆代码，而不是拆决策。
4. 不标证据，把推断当事实写；或者照抄宣传文案。
5. 相信 AI 说的"已完成""官方写了"，没有回原文核对。
6. 只走正向流程，没有故意走一次异常。
7. 以为所有产品都是 Agent。能穷举的就是 Workflow。
8. 多 Agent 串联却不分析确认点，忽略了成功率连乘和积分白扣。
9. 只列模型不算账；或者编了单价；或者没算免费用户的成本。
10. 把"接了很多模型"当壁垒。模型是买得到的。
11. 只夸不批，没有「它没做好的地方」和「如果我来做」。
12. 什么都往里塞，没按目的控制深度。

## 自检清单（交付前逐项过）

- [ ] 目的和深度在开头写清了
- [ ] 五层齐全、顺序正确，上下层能串成链（02 的步骤 → 03 的分工 → 04 的模型 → 05 的壁垒）
- [ ] 一句话定位套用了公式，"谁"足够具体；B 端写了三个人
- [ ] 按产品体验流程跑了至少三轮（模糊 / 具体 / 故意异常）并有体验记录表，或者已经向用户要了截图清单；没有替用户登录或付款
- [ ] 旅程图有正向五步和异常四条；写了替代了什么工作流；测评打分合计 100
- [ ] 人机分工表的每个确认点都写了"为什么要人"（成本高 / 主观 / 担责）
- [ ] 光谱定位有外部信号作依据；单 Agent 写全了输入输出 / 任务 / 工具 / 规则
- [ ] 模型清单每行有四项和理由；成本账有公式，没有编造的单价
- [ ] 壁垒先划掉了买得到的；写了数据飞轮和最厚的一层
- [ ] 每条结论都有证据标签；所有【待确认】都进了文末清单并写了核实方法
- [ ] 有架构图（名词框 + 证据标签）、PM 结论、「如果我来做」
- [ ] （如生成了报告）HTML 里的结论和标签与文档一致，没有新增内容
