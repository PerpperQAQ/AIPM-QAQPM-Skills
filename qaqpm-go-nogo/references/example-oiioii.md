# 示例：OiiOii 浓缩拆解（对齐深度用）

> 依据：老师认可的标准化拆解文档《以 OiiOii 为例拆解一个 Multi Agent 平台》（截图时点约 2025-12），以及课堂白板。这里只保留"合格深度"的骨架，用来对照，**不能当作 OiiOii 的最新事实**，产品和价格可能已经变了。
> 标签说明：【事实】= 示例文档截图或官网可见；【推断】= 示例作者或课堂的推论；【待确认】= 来源矛盾或没有公开。

## 01 用户需求场景

- **一句话定位**【推断】：一款给半专业和非专业动画创作者（PUGC/UGC）用的、在制作剧情动画短片、MV、科普和 IP 二创时、解决"一个人带不动整条动画管线"问题的多 Agent 动画制作平台。
  - 依据：官网写着「导演，我们是您的专业 AI 动画代理团队」【事实】；创始人说"只专注动画，一切以交付动画成片为目标"【事实·访谈】。
  - 课堂白板的版本是"个人或小团队，做红果类漫剧，快速生成"；但创始人表示漫剧不是主攻方向【事实】→ 以文档为准，场景写"动画短片"。
- **市场**【事实·研报】：短剧市场已超过 500 亿，漫剧市场有望突破 200 亿；2025 年被称为漫剧元年，成本可以压到传统做法的 1/5–1/10。
- **竞争格局**：工具层有巨日禄（服务专业漫剧团队，用户为效率和成本买单）vs OiiOii（独立动画创作者，用户为质量和叙事完成度买单）【推断】；平台层是抖音、快手、红果、爱奇艺等，靠分账扶持【事实】；模型厂商层是 Seedance、可灵等【事实】。
- **差异化**【推断】：做"动画垂直 + 交付导向"，而不是全模态工作台。Agent 按行业岗位命名，用户像在"远程带一个动画团队"；托管模式（一句话跑完）和对话模式（每一步都能插手）同时照顾小白和专业用户。
- **商业模式**【事实·会员页】：按月订阅积分（单位叫"盒饭"）。FREE 每日签到 100；BASE $9 → 1000（约 143 张图或 600 秒视频）；STAR $25 → 3000；PRO $84 → 8000；另有企业版。档位越高，并发分镜越多，还有去水印、1080p、更稳定的模型服务。
- **种子用户**【事实】：内测阶段近 10 万人排队申请；首页展示案例，让人看到能做什么。

## 02 用户层

- **功能模块**【事实】：快速生视频、Oii 生图、音乐概念短片（快速，即时满足）· 剧情故事短片（专业，7 个 Agent 依次协作）· 衍生品设计（创意）；另有我的项目和角色库。
- **正向五步**：
  - 入口：首页输入框选模式，例如「剧情故事短片 /」【事实】
  - 输入：一句话或分镜文本，可以拖入参考图【事实】
  - 过程：左边是对话群（各 Agent 依次"进群"），右边是固定画布，按剧本 → 角色 → 场景 → 分镜 → 成片展示【事实】
  - 输出：分镜视频和成片【事实】
  - 交付：下载；付费档才能去水印和导出 1080p【事实】
- **异常四条**：信息给不全时，追问或推表单卡片【事实】；失败退不退盒饭【待确认】；中途改主意可以回退到某个 Agent，单个分镜也能重建【事实】；不满意时可以局部修改单镜头或单角色【事实】。
- **逆向流程**【推断】：在角色设计师和分镜师环节确认"不满意"，就回到上一步重做。
- **替代的工作流**【推断】：原来是艺术总监、编剧、角色和场景设计、分镜、动画、剪辑、配音一整个团队，周期以月计；现在用户只负责提需求和在几个确认卡片上做选择。
- **测评**（场景：30 秒武侠茶馆，3 个分镜）：成品质量 13/20、一致性 19/20、意图理解 14/15、反馈灵活性 8/10、多 Agent 协作 14/15、知识运用 9/10、模型调度 5/5、资产复用 5/5，合计 **87，落在 70–89 档**（流程通顺，少量干预后效果不错）。
  - 注：原文档写的权重（40/20/25/15）和各维度满分加总（40/25/25/10）对不上。模板里已经改成"权重 = 满分"。

## 03 技术层

- **光谱定位**【推断】：多 Agent，串行。依据：岗位化的 Agent 依次进群，上一步确认后下一步才开始，过程里每个步骤都打勾。
- **Agent 组成**：7 个【事实·截图】：艺术总监（主 Agent，负责理解、澄清、拆解需求和路由）→ 编剧 → 角色设计师 → 场景设计师 → 分镜师 → 音乐总监；衍生品场景由产品设计师接手。课堂白板推断"没有主 Agent"，与文档不一致，以文档为准。
- **人机分工（节选）**

| 步骤 | AI 做 | 人做 | 确认点 | 为什么要人 |
|---|---|---|---|---|
| 需求初判 | 判断有没有分镜、剧情、角色设定 | 补充缺失的信息 | 追问 | 主观 |
| IP 识别 | 识别 IP 角色 | 选模型 | 风险前停（卡片） | 担责（版权） |
| 基础设置、风格、情绪 | RAG 推荐风格，生成情绪词 | 选定 | 表单卡片 | 主观 |
| 剧本和报价 | 写剧本，按角色数、分镜数、音效数计价 | 确认报价单 | 动手前审方案 | 成本高 |
| 角色、分镜生成 | 生成主图、三视图、分镜视频 | 满意或重做 | 逐个确认 | 主观 + 成本高 |
| 合成 | 代码按顺序拼接（不需要 AI） | — | 无 | — |

- **单 Agent：艺术总监**【推断】：输入是用户需求和表单回填；输出是结构化 Brief（project_id、technical_spec、visual_style_tags、emotional_tone）；工具有追问、四类表单卡片、search_film_style（RAG）、manage_global_context、rollback_state、dispatch_agent；规则是不准跨步、风格只能从检索候选里选、确认后才写入、只输出 JSON。架构选 Planner-Executor 而不是 ReAct，因为链路长、耦合高，需要审批流和断点回滚。
- **全局上下文**【推断】：相当于项目 PRD，包含项目元数据、剧本字段、角色字典（含主图和三视图 URI）、分镜资产流水线（shot_id、台词、时长、actor_refs）。角色一致性就靠 URI 强引用来保证。
- **没做好的地方**【事实·截图】：分镜师把同一句"我将为您执行此操作"重复了约 6 次，却没有真正往下走 → 可能原因是工具调用失败或状态没更新 → 改法：提示词要求"确认即调用"；工具层在状态为 confirmed 时幂等返回；主 Agent 检测到重复输出就介入。

## 04 模型层

- **模型清单**：界面上能看到自有命名的模型 Oii_Na（生图）和 Oii_S2（IP 场景可选）【事实】，背后具体对应哪个模型【待确认】。文档列出的生图模型有 Nano Banana Pro、Seedream 4.5、MJ V6、SD；生视频有 Sora 2、SeeDance 2.0、Kling、海螺、Vidu 等；音频有 TTS + BGM + SFX【推断，文档自己的数量前后矛盾】。文本模型【待确认】。
- **路由**【推断】：先和风格库匹配，再按镜头特点（打斗、运镜、文戏）选模型；IP 场景交给用户选。
- **强模型 vs 聪明流程**【推断】：画质依赖强生图和生视频模型；一致性主要靠流程设计（主图 → 三视图 → 用 URI 引用；单镜头控制在 8–10 秒）。
- **成本估算**【推断】（收入侧按 BASE 档：$9 ÷ 1000 ≈ $0.009 / 盒饭；一张图约 7 盒饭，一秒视频约 1.7 盒饭）：
  - 30 秒、3 镜：9 张图（3 张主图 + 3 张三视图 + 3 张场景图）约 63 盒饭，加 30 秒视频约 50 盒饭，再按重抽系数 1.5 算，约 170 盒饭，折合约 $1.5。一个 BASE 月包大约能做 6 条。
  - 模型侧成本【待确认】：要查各模型单价才能算毛利。课堂口述"一条完整视频要 1000 多积分，约 100 多元"【待确认】，和上面的量级差很多，可能是长片或多轮重抽，需要实测扣费核对。
- **省钱手段**【推断】：在剧本阶段先出报价单再动手；逐镜头确认，避免整片白扣；免费档靠签到限流。

## 05 基础层

- **买得到**：各家模型 API、算力、通用工具。
- **买不到**【推断】：动画工艺流程的算法化表达（Agent 管线、提示词、skill）、风格库、影视专业知识库、"模型表现得分"知识、剧本数据、用户资产（角色库）和用户反馈。
- **数据飞轮**【推断】：角色库和项目资产（可复用）、会话里的"差点意思 / 重建"（就是 badcase）、风格库、skill → badcase 库 → 评测集 → 调风格库映射、提示词和路由。接入新模型时，要重新评测它对各种风格的适配度。
- **最厚的一层**【推断】：技术层（工艺流程编排）加基础层（风格和知识库）。所以这类团队要的 PM 懂影视流程和多 Agent 编排。

## 汇总

**架构图（名词版）**：
- 用户层：项目创作 · 我的项目 · 角色库 · 托管 / 对话模式【事实】
- 应用层：艺术总监（主）· 编剧 · 角色设计 · 场景设计 · 分镜 · 音乐总监 · 产品设计【事实】；工具有上下文管理、状态管理、表单、追问、分镜拆解、成本估算、RAG【推断】
- 模型层：图片 · 视频 · 音频 · 文本【待确认】
- 基础层：风格库 · 视频知识库 · 模型表现得分 · 剧本数据 · 用户反馈【推断】

**PM 结论**：
- 体验：把 Agent 拟人化成岗位"进群"，小白知道该找谁改什么。
- 边界：只做动画。
- 信任：过程完全透出，每一步卡片确认，先出报价单。
- 如果我来做：先修好状态机，解决重复确认的循环；把失败退盒饭的规则写清楚并在界面上展示；把用户的"差点意思"自动归类进 badcase 库。
