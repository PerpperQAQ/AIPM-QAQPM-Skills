# 产品体验流程（亲手跑一遍）

> 目标：拿到能支撑 02 用户层和 03 技术层的**一手证据**，而不是复述宣传文案。体验的结果会直接喂给 02 的测评打分和 03 的反推。

## 1. 选择体验路径（按顺序尝试）

| 顺序 | 条件 | 做法 |
|---|---|---|
| ① | 是网页产品，且运行本 skill 的 Agent 有浏览器操作类工具 | Agent 自己打开网页亲手用，每一步截图 |
| ② | Agent 用不了（只有 App / 移动端、拦截自动化操作、没有浏览器工具） | 先搜公开的演示视频、图文测评、官方教程和帮助中心，从中截取关键帧 |
| ③ | ② 仍然缺证据 | 给用户一份**具体的截图清单**，请用户自己操作后补图（清单见 §5） |

用户已经提供了截图或录屏时，直接按编号分析，缺的部分再走 ②③。

## 2. 安全和花费边界

- **登录、注册、手机或邮箱验证码、人机验证、实名认证、付款，一律交给用户本人操作。** Agent 不输入账号密码，不读取或保存凭证，不替用户付款。遇到这些步骤就停下来，请用户接管，完成后再继续。
- **只用免费额度。** 需要消耗付费积分、开会员或者购买时，先告诉用户预计会花多少、为什么值得花，得到同意后再继续。
- 不在产品里公开发布作品，不对外发送内容，不改账号设置，除非用户明确要求。
- 涉及个人隐私的素材（真人照片等），只用用户提供或明确同意使用的。

## 3. 测试脚本（至少 3 轮，外加边界探测）

| 轮次 | 怎么测 | 想看什么 |
|---|---|---|
| ① 模糊需求 | 一句话、信息不全，例如"帮我做个视频" | 会不会追问或推表单 → 需求澄清分支、确认点 |
| ② 具体需求 | 真实场景下的完整需求（风格、时长、对象都给全） | 正常主流程、过程透出、端到端质量 |
| ③ 故意异常 | 从下面选几项：**信息给不全**（只答一半）· **中途改主意**（做到一半改风格或剧情）· **只改一部分**（只改一个镜头或段落）· **失败与退费**（触发超时或违规，看提示和积分有没有退回） | 异常四条的处理方式、回退机制、状态管理 |
| ④ 边界探测 | 能力范围外的请求、敏感或涉 IP 的内容、超长或超大的输入、完全不同的任务类型 | 能力边界、合规拦截、换个任务后步骤会不会变（判断 Workflow 还是 Agent） |

拿不准时，换一个任务再跑一次。

## 4. 每一步记录什么（对应正向五步）

| 五步 | 必记 | 反推什么 |
|---|---|---|
| 入口 | 从哪进、默认文案、有哪些模式和模板 | 定位、目标用户 |
| 输入 | 让你给什么（对话 / 表单 / @引用 / 上传）、有哪些默认值 | 输入契约 |
| 过程 | **过程文案、状态文字、思考过程** · **选择框和卡片**（固定几个选项）· **任务打勾 / 进度** · **推荐结果**（从大库里给出前 N 个）· Agent 或角色名 · **等待时长** | 系统提示词 · tool · 状态管理 · RAG · 多 Agent 分工 · 成本和模型 |
| 输出 | 产出物是什么、质量如何（按 02 的测评维度打分）、有没有瑕疵 | 能力上限、模型档位 |
| 交付 | 能不能直接用、还要改多少、导出格式、有没有水印 · **本次消耗的积分 / 额度** | 付费点、单任务成本 |

每张截图按顺序编号（#1、#2……），文件名或描述里注明它属于哪一轮、哪一步。

## 5. 截图清单（请用户补图时用，按需删减）

1. 首页或入口（含模式选择、模板）
2. 输入界面（输入框、表单、默认文案）
3. 提交前的扣费或额度提示
4. 生成过程中的状态和思考文案、进度或任务打勾
5. 所有选择卡片或选项框（风格、模型、确认）
6. 最终输出，以及导出或下载页
7. 模糊需求时它的追问
8. 中途修改或局部修改的入口和结果
9. 失败或报错页，以及失败后的积分变化
10. 价格页或会员页、积分规则、模型下拉框

## 6. 体验记录表（模板）

| # | 轮次 | 步骤（五步） | 我的操作 | 页面表现（原文） | 截图编号 | 耗时 | 消耗（积分 / 额度） | 反推线索 | 证据标签 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | ①模糊 | 输入 | 输入"做个视频" | 弹出表单：时长 / 比例 / 语言 | #3 | 5s | 0 | 固定表单 → 表单 tool；缺字段就追问 | 【事实】截图 / 【推断】tool |
| | | | | | | | | | |

"页面表现"写原文，不写转述；"反推线索"写推出了什么，以及对应 03 的哪一项。

## 7. 结果怎么用

- **→ 02 用户层**：填用户旅程图（正向五步 × 四行）和异常四条；按测评维度给出分数，每个分数都要能指回截图编号。
- **→ 03 技术层**：把"反推线索"一列整理成光谱定位依据、Agent 组成、工具清单、状态管理和上下文的推断，以及「它没做好的地方」。
- **→ 04 模型层**：模型下拉框、扣费记录和等待时长，用于模型清单和成本估算。
- 没测到的项写进「待核实清单」。

## 8. 纪律

- 产品或 Agent 说「已完成 / 已生成 / 已退款」时，**回页面看结果是否真的存在**（文件能打开、积分确实变了），没看到就不标【事实】。
- 只记录看到的；猜测标【推断】或【待确认】。
- 自己 Agent 的操作也一样：说"已截图""已提交"之前，先确认截图文件存在、页面状态已经变化。
